
# 1. Сущности резервного копирования

## Full Backup (Полный образ)

### Суть/Смысл

Полный образ — это эталонный снимок выбранного объекта:

```text
Система
Раздел
Диск
```

В образ попадают:

```text
EFI
MSR
Recovery
Windows
BCD
Реестр
Программы
Пользовательские данные
```

На уровне диска создается копия всех используемых блоков файловой системы.

---

### Когда применять

* Первичная точка восстановления.
* Перед обновлением BIOS.
* Перед заменой SSD.
* Перед экспериментами с драйверами.
* Перед созданием WTG.

---

### Как работает на уровне диска

Пример:

```text
SSD = 500 ГБ
Занято = 120 ГБ
```

Программа анализирует NTFS и копирует только занятые блоки.

Итог:

```text
Не 500 ГБ
а примерно 120 ГБ
```

---

### Ключевые концепции

#### Block-Level Backup

Копируются блоки:

```text
MFT
NTFS metadata
EFI
BCD
```

Преимущества:

```text
Полное восстановление загрузки
Максимальная скорость
```

---

#### File-Level Backup

Копируются файлы:

```text
*.exe
*.dll
*.docx
```

Недостатки:

```text
Не сохраняются GPT
EFI
BCD
```

Для восстановления Windows предпочтителен Block-Level.

---

## Differential Backup (Дифференциальный образ)

### Суть/Смысл

Сохраняются все изменения относительно последнего Full Backup.

Пример:

```text
Day 1
Full = 100 ГБ

Day 2
Diff1 = 2 ГБ

Day 3
Diff2 = 5 ГБ

Day 4
Diff3 = 8 ГБ
```

Каждый новый Differential содержит накопленные изменения с момента Full.

---

### Когда применять

* Домашняя рабочая станция.
* WTG.
* Инженерный SSD.
* Когда важнее надежность, чем экономия места.

---

### Как работает на уровне диска

Система сравнивает:

```text
Текущее состояние
vs
Full Backup
```

и сохраняет изменившиеся блоки.

---

### Ключевые концепции

Для восстановления нужны:

```text
Full
+
нужный Differential
```

Например:

```text
Full
Diff1
Diff2
Diff3
```

Для восстановления точки Diff3 потребуется только:

```text
Full
+
Diff3
```

---

## Incremental Backup (Инкрементный образ)

### Суть/Смысл

Сохраняются изменения относительно предыдущей точки.

Пример:

```text
Full = 100 ГБ

Inc1 = 2 ГБ
Inc2 = 3 ГБ
Inc3 = 1 ГБ
```

---

### Когда применять

* Максимальная экономия места.
* Частые точки восстановления.
* Ограниченный объем накопителя.

---

### Как работает на уровне диска

Каждый новый инкремент хранит только новые изменения.

---

### Ключевые концепции

#### CBT (Changed Block Tracking)

CBT отслеживает изменившиеся блоки.

Без CBT:

```text
Сканирование всех 120 ГБ
```

С CBT:

```text
Сканирование только изменившихся блоков
```

Например:

```text
Изменилось 500 МБ

Сканируется:
500 МБ
вместо
120 ГБ
```

---

### Влияние на скорость

CBT существенно уменьшает:

```text
Время создания образа
Нагрузку на SSD
Количество чтения
```

---

### Недостаток

Для восстановления требуется вся цепочка:

```text
Full
+
Inc1
+
Inc2
+
Inc3
```

Повреждение одного звена ломает все последующие.

---

## Compressed Backup (Сжатый образ)

### Суть/Смысл

Это не отдельный тип резервной копии.

Это режим хранения:

```text
Full + Compression
Differential + Compression
Incremental + Compression
```

---

### Когда применять

Практически всегда.

Для i7-12700H потери производительности минимальны.

---

### Как работает на уровне диска

Сначала:

```text
Чтение блоков
```

Потом:

```text
Сжатие
```

Потом:

```text
Запись образа
```

---

### Влияние на скорость

| Режим          | Размер         | Скорость                |
| -------------- | -------------- | ----------------------- |
| No Compression | Максимальный   | Максимальная            |
| Low            | Немного меньше | Почти без потерь        |
| Medium         | Оптимально     | Незначительно медленнее |
| High           | Минимальный    | Самый медленный         |

# 2. Оценка утилит

## DiskGenius (DGEng6201821_x64)

### Рейтинг эффективности

**8/10**

### Ключевые возможности

```text
System Backup
Disk Backup
Partition Backup
Incremental Backup
Differential Backup
Compression
VSS Hot Backup
Disk Clone
System Migration
```

Дополнительно:

```text
GPT Repair
Partition Recovery
HEX Editor
File Recovery
```

---

### Ограничения/Риски

1. Backup-модуль не является основной специализацией продукта.
2. Менее развитое управление цепочками инкрементов.
3. Менее развитые политики хранения резервных копий.
4. Нет такого уровня автоматизации как у специализированных backup-решений.
5. Собственный формат образов.
6. Интерфейс восстановления менее дружелюбен для начинающих.

### Рейтинг эффективности

**10/10**

### Ключевые возможности

```text
System Backup
Disk Backup
Partition Backup
Incremental
Differential
Compression
Scheduler
Retention Policy
WinPE Recovery
Disk Clone
System Clone
```

---

### Ограничения/Риски

1. Формат ADI зависит от Hasleo.
2. Для восстановления желательно иметь совместимую версию Hasleo.
3. Потеря Full делает бесполезными связанные Diff/Inc.
4. Длинные цепочки Incremental увеличивают риск восстановления.
5. Differential со временем может приближаться по размеру к Full.
6. Нет открытого стандарта хранения образов.


```text
Минимальный размер резервных копий

```

---

### Если цель — изучение структуры дисков и резервирование одновременно

```text

```

Потому что:

```text
Backup

```
