[MAIN] Техническое решение

### 1. 📘 Руководство (Guide): Принцип работы
`.gitignore` — **фильтр на этапе сканирования** рабочего каталога. Он не чистит репозиторий, а запрещает Git'у отслеживать изменения файлов, соответствующих паттерну.
**Ключевые инварианты:**
- Применяется **до** `git add`. Если файл уже в `.git/index`, паттерн игнорируется до явного `git rm --cached <file>`.
- Читается **сверху вниз**. Последнее совпадающее правило побеждает.
- Работает рекурсивно, но локальные `.gitignore` в подпапках переопределяют только свои директории.

### 2. 📋 Шпаргалка (Cheat Sheet): Синтаксис паттернов
| Паттерн | Логика | Пример | Матчит | НЕ матчит |
|---------|--------|--------|--------|-----------|
| `*` | 0+ символов (кроме `/`) | `*.log` | `app.log` | `logs/app.log` |
| `?` | Ровно 1 символ | `test?.py` | `test1.py` | `test10.py` |
| `[0-9]` | Символ из диапазона | `data_[0-9].csv` | `data_3.csv` | `data_10.csv` |
| `**/` | Рекурсия по вложенным папкам | `**/dist` | `dist`, `src/build/dist` | - |
| `/` в конце | Только директория | `__pycache__/` | Папка `__pycache__` | Файл `__pycache__` |
| `/` в начале | Только от корня текущего `.gitignore` | `/env` | `env/` (в корне) | `src/env/` |
| `!` | Инверсия (разрешить) | `!config.local.yaml` | Отменяет предыдущий игнор | Требует предварительного игнора |
| `\` | Экранирование спецсимволов | `\#notes.md` | Файл `#notes.md` | Не как комментарий |

### 3. 📖 Мануал (Reference): Глубокая спецификация
- **Приоритет файлов:** `.gitignore` в корне → `.gitignore` в подпапке → глобальный `~/.gitignore_global` (задается через `git config core.excludesFile`). Конфликты разрешаются по специфике пути, последнее правило в одном файле перебивает предыдущие.
- **Отладка:** `git check-ignore -v <path>` выводит точную строку и файл, который применил правило. Стандарт для диагностики.
- **Связь с индексом:** Git хранит состояние трекинга в `.git/index`. Добавление в `.gitignore` меняет только *будущие* сканы. Для уже закоммиченных: `git rm --cached <file>` (сохраняет на диске, убирает из индекса) → commit → `.gitignore` начинает работать.
- **Глобальные исключения:** Рекомендуется выносить `.DS_Store`, `Thumbs.db`, `.idea/`, `.vscode/settings.json` в `~/.gitignore_global`, чтобы не засорять репозиторий.

**Ловушки (TRAPS):**
- `*.log` не игнорирует `logs/app.log`. Используйте `**/*.log` или `logs/`.
- `!important.txt` сработает **только** если выше есть `*.txt` или `important.txt`. Инверсия не создает разрешений из воздуха.
- WSL2 case-sensitive, Windows часто нет. Пишите паттерны в нижнем регистре.
- Никогда не игнорируйте `.gitignore` в корне репо. В подпапках допустимо, но усложняет аудит.

🎓 **Ментор: Архитектура & Масштабирование**
• **Почему `git rm --cached`?** Git разделяет `working tree` (файлы на диске), `index` (staging), и `objects` (история). `.gitignore` влияет только на скан `working tree → index`. `rm --cached` разрывает связь в `index`, позволяя фильтру вступить в силу.
• **Конфликты Docker:** Docker монтирует хост-папки в контейнер. `.gitignore` не влияет на `volume mounts`. Используйте `.dockerignore` для сборки образов (аналогичный синтаксис), чтобы не тащить `node_modules/`, `.venv/`, `.git/` в layer.
• **Масштаб:** При >5 разработчиках автоматизируйте проверку через `pre-commit` хук + `gitignore.io API`. Это исключает рассинхрон локальных игноров.



[RECOMMEND]
1. Настройте глобальный `.gitignore` для IDE/Win11 мусора: `git config --global core.excludesFile ~/.gitignore_global`
2. Добавьте `git check-ignore -v <path>` в чек-лист при странных `git status`.
3. Используйте `.dockerignore` зеркально к `.gitignore` для CI/CD-образов.
