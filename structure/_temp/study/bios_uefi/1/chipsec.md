[MAIN] 🚩 Справочник флагов `chipsec_main.py` (v1.12+)

| Флаг | Полный аналог | Назначение | Режим доступа | Пример |
|------|---------------|------------|---------------|--------|
| `-m` | `--module` | Выбор модуля/группы для запуска | **Read-only** | `-m common` / `-m secureboot` / `-m uefi` |
| `-j` | `--json` | Экспорт результатов в JSON | Read | `-j audit.json` |
| `-l` | `--log` | Сохранение консоли в лог-файл | Read | `-l diag.log` |
| `-v` | `--verbose` | Детальный вывод этапов проверок | Read | `-v` |
| `-d` | `--debug` | Режим отладки (raw-регистры, трассировка) | Read | `-d` |
| `-r` | `--report` | Генерация HTML/XML отчёта | Read | `-r report.html` |
| `--list_modules` | — | Вывод всех доступных модулей с описанием | Read | `--list_modules` |
| `-p` | `--platform` | Принудительный выбор платформы (авто-детект обычно точен) | Read | `-p SKL` |
| `--helper` | — | Выбор OS-драйвера (`windows`, `linux`, `efi`, `dal`) | Read | `--helper linux` |
| `--fix` | — | Попытка авто-исключения (только в модулях, где реализовано) | **Write** (требует подтверждения) | `-m secureboot --fix` |

⚠️ **Архитектурное правило**: `chipsec` по умолчанию **только читает** регистры, память, NVRAM и ACPI. Запись возможна только в узком классе модулей при явном указании `--fix` или ручном вызове методов. В диагностике и ремонте запись **не используется**.

[MAIN] 🛠️ Практический гайд: безопасный воркфлоу с флагами

### 📋 Этап 0: Подготовка (Win11)
```powershell
# 1. Запуск от Администратора + тестовая подпись (для драйвера)
bcdedit /set testsigning on
# Перезагрузка

# 2. Установка
git clone https://github.com/chipsec/chipsec.git
cd chipsec
pip install -r requirements.txt
python setup.py build_ext --inplace
```

### 🔍 Этап 1: Базовый скан (комбинация флагов)
```powershell
# Полная проверка платформы + JSON + Лог + Детали
python chipsec_main.py -m common -j audit.json -l full_scan.log -v

# Расшифровка флага:
# -m common    → запускает группу "common" (SecureBoot, SPI, TPM, SMM, UEFI vars)
# -j ...       → машиночитаемый отчёт для скриптов
# -l ...       → текстовый лог для архива/клиента
# -v           → показывает, какие именно регистры/переменные проверялись
```

### 🎯 Этап 2: Целевой аудит (по симптомам)
| Симптом | Команда | Что выведет `-v` |
|---------|---------|------------------|
| "Secure Boot выключился сам" | `-m secureboot -v` | Статус `PK`/`KEK`/`db`/`dbx`, `SetupMode`, хеши загрузчиков |
| "Прошивка не обновляется / ошибка SPI" | `-m spi_lock -v` | Состояние `BIOSWE`, `SMM_BWP`, `FLOCKDN` (заблокирован ли регион) |
| "TPM не определяется в Windows" | `-m tpm_config -v` | Версия TPM2.0, состояние `PPI`, `PCRs`, `Firmware Version` |
| "Подозрение на SMM-руткит" | `-m smm -v` | Защита `SMRAM`, наличие `SMM Communication`, `DMA` защита |

### 📊 Этап 3: Автоматизация и отчётность
```powershell
# 1. HTML-отчёт для визуального анализа
python chipsec_main.py -m common -r report.html

# 2. Парсинг FAILED/WARNING из JSON (PowerShell)
$json = Get-Content audit.json | ConvertFrom-Json
$json.modules | Where-Object { $_.result -in "FAILED","WARNING" } | 
  Select-Object name, result, description | Format-Table -AutoSize
```

### ✅ Этап 4: Интерпретация результатов
| Статус | Значение | Действие инженера |
|--------|----------|-------------------|
| `PASSED` | Соответствует baseline | Нет действий |
| `FAILED` | Критичное отклонение от спецификации | Проверить BIOS настройки, обновить прошивку, заменить модуль |
| `WARNING` | Отклонение допустимо или требует контекста | Сверить с мануалом вендора (часто: `SPI lock` на dev-платах) |
| `NOTAPPLICABLE` | Функция не реализована в этой платформе | Игнорировать |

[IF SOFT] 🎓 Ментор: ловушки и best practices
- `Почему chipsec не ломает систему?` → Фреймворк использует только `READ` операции через kernel-driver. Запись требует явного вызова `write_register`/`write_pci_cfg`, который в стандартных модулях отключён.
- `Как не запутаться в флагах?` → Используй шаблон: `-m <группа> -j <файл> -v`. Это покрывает 95% диагностических задач.
- `False positives` → `WARNING` на `spi_lock` часто нормален для consumer-ноутбуков (вендор блокирует SPI только в SMM). Читай `description`, а не только статус.
- `Драйвер не грузится` → Проверь `bcdedit /set testsigning on`, отключи Secure Boot временно, запусти `python setup.py install`. Если ошибка `Access Denied` → запускай из консоли `Admin`.
- `Масштабирование` → После освоения `-m common` переходи к `--list_modules`, выбирай узкие проверки (`chipsec.modules.common.uefi.secureboot`). Интегрируй `audit.json` в тикет-систему мастерской.

[ANTICIPATE]
- "Как запустить chipsec из WinPE/Ventoy?" → Скопируй папку `chipsec/` на флешку, загрузи WinPE, установи драйвер `chipsec_wdd.sys` через `drvload`, запусти `python chipsec_main.py -m common`. Требуется `testsigning` в PE-образе.
- "Можно ли проверить конкретный регистр без модуля?" → Да: `chipsec_util.py mmio read <address> <size>` или `pci read <bus> <dev> <func> <offset>`. Но для диагностики лучше использовать модули — они валидируют значения против спецификации.
