# 📋 БЛОК 02: Установка Windows и вход в Audit Mode (ИТОГОВАЯ ВЕРСИЯ)

## 🎯 Цели блока

| Цель | Обоснование |
|:---|:---|
| Развернуть чистую базовую ОС Windows 10/11 Pro в изолированной среде | Без сети исключается фоновое обновление AppX-пакетов, которое ломает Sysprep |
| Войти в режим аудита (Audit Mode) под встроенным Administrator | Audit Mode — единственная среда, позволяющая модифицировать систему до создания пользовательского профиля |
| Избежать создания лишних профилей | Каждый профиль = потенциальный источник рассинхронизации AppX при Sysprep |
| Создать точку отката (снимок ВМ) | Защита от ошибок на последующих этапах блокировки служб |
| Установить английскую раскладку по умолчанию | Гарантия корректного ввода всех CMD/PowerShell команд на всех последующих этапах |

## 🛠️ Действия блока

### ДЕЙСТВИЕ 02.1. Проверка конфигурации ВМ перед запуском

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Сетевой адаптер** | Отключен (галочка «Подключить кабель» снята) | Полная изоляция от WU/telemetry. Критично для чистоты AppX. | Фоновое обновление AppX → Sysprep crash |
| **Чипсет** | PIIX3 | Стабильнее ICH9 в VirtualBox 7.2.x (подтвержденный баг Forum #114041 с зависанием при shutdown) | Зависание ВМ при завершении работы |
| **EFI** | Включено | Жесткое требование для UEFI-развертывания на физическом железе | Образ развернется в MBR, неприменим для современных ПК |
| **Secure Boot** | **Выключено** | Позволит загружаться с кастомных WinPE (Sergei Strelec, DiskGenius) для захвата образа | Невозможность загрузить WinPE для захвата WIM |
| **Видео** | **VBoxSVGA**, 3D Выкл | Единственный штатный контроллер для Windows. VMSVGA предназначен для Linux. 3D вызывает BSOD в 7.2.x | BSOD, черный экран, конфликты WDDM |
| **USB** | **3.1 (xHCI)** ⚡[EXTENSION PACK] | Захват нативных драйверов `usbhub3.sys`/`usbxhci.sys` для физического железа. Требует Extension Pack | Legacy-драйверы на физическом USB 3.0+ → снижение скорости I/O |
| **Hot-Plug VDI** | Подключен как SATA порт 1, флаг **Hot-Pluggable** включен | Механизм обмена файлами без Guest Additions (не загрязняет PnP-дерево) | Нет способа передать скрипты/обновления в изолированную ВМ |
| **ISO-образ** | Смонтирован в IDE/SATA CD-привод | Установочный носитель Windows 10/11 Pro | Невозможность начать установку |
| **Оперативная память** | 4096-8192 МБ | Достаточно для ресурсоемкой очистки WinSxS (DISM ResetBase) | Нехватка RAM при работе DISM → сбой |
| **Общий буфер обмена** | Выключено | Исключает фоновые процессы VBoxTray.exe | Утечки памяти перед Sysprep |
| **Drag'n'Drop** | Выключено | Блокирует лишнюю активность шины данных | Межпроцессные прерывания |
| **Гостевые дополнения (Guest Additions)** | **КАТЕГОРИЧЕСКИ НЕ УСТАНАВЛИВАТЬ** | Внедряют в ядро неудаляемые драйверы VBox, вызывающие BSOD на физическом железе | Невозможность деплоя на реальный ПК |

**Проверка перед запуском:**
```
VirtualBox Manager → Выбрать ВМ → Настройки → Проверить все параметры выше
```

### ДЕЙСТВИЕ 02.2. Загрузка установщика и выбор редакции

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Запуск ВМ** | Двойной клик по ВМ в VirtualBox Manager | Стартует загрузка с ISO | — |
| **Нажатие клавиши** | Любая клавиша при появлении «Press any key to boot from CD or DVD» | Инициализирует загрузчик Windows PE | Пропуск → загрузка в существующую ОС (если есть) |
| **Язык для установки** | **Русский** | Локализация интерфейса установщика | Неверный язык → неудобство работы |
| **Формат времени и валюты** | **Русский (Россия)** | Соответствие региональным настройкам клиента | Несоответствие форматов даты/времени |
| **Метод ввода (раскладка)** | 🔴 **Английский (США)** | **КРИТИЧНО:** Все команды CMD (`OOBE\BYPASSNRO`), пути (`C:\Windows\...`), PowerShell-скрипты (`Get-AppxPackage \| Remove-AppxPackage`) содержат латинские буквы, слэши, пайпы. В русской раскладке буквы находятся на других клавишах → команды будут введены неверно. | При русской раскладке `OOBE\BYPASSNRO` превратится в `ЩЩЕЁ\ИПФУНШ` → команда не выполнится |
| **Кнопка «Установить»** | Нажать | Запуск процесса установки | — |
| **Активация** | «У меня нет ключа продукта» | Активация произойдет позже на физическом железе (Digital License) | Ввод ключа → привязка к ВМ, проблемы при деплое |
| **Редакция Windows** | 🔴 **Windows 10/11 Профессиональная (Pro)** | Только Pro поддерживает `gpedit.msc` и полноценный Sysprep | Home/Education → отсутствие gpedit, ограничения Sysprep → невозможность сборки Golden Image |
| **Лицензионное соглашение** | Принять | Обязательное условие установки | Отказ → остановка установки |
| **Тип установки** | **Выборочная: только установка Windows (для опытных пользователей)** | Позволяет контролировать разметку диска | Обновление → попытка сохранить данные, риски конфликтов |
| **Разметка диска** | Выбрать «Незанятое пространство» → Далее | VirtualBox сам создаст EFI + MSR + Windows разделы | Ручная разметка → риски ошибок для ВМ |
| **Ожидание установки** | 10-20 минут | Копирование файлов, установка компонентов, перезагрузки | Прерывание → повреждение установки |

**⚠️ КРИТИЧНО ПОСЛЕ УСТАНОВКИ:**
Система перезагрузится и начнет процесс OOBE (Out-of-Box Experience). На первом экране (выбор региона) **НЕ СОЗДАВАЙТЕ ПОЛЬЗОВАТЕЛЯ** — мы войдем в Audit Mode.

### ДЕЙСТВИЕ 02.3. Обход сетевых ограничений OOBE (BYPASSNRO)

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Экран OOBE** | Экран выбора региона/языка (первый экран после установки) | Точка входа для обхода требований Microsoft | Пропуск → система потребует интернет и Microsoft Account |
| **Проверка раскладки** | Убедиться, что раскладка **ENG** (английская) | Команда `OOBE\BYPASSNRO` содержит только латинские символы | В русской раскладке команда введется неверно |
| **Вызов консоли** | `Shift + F10` (или `Fn + Shift + F10` на ноутбуках) | Открывает командную строку в контексте установщика | Неверная комбинация → консоль не откроется |
| **Команда обхода** | `OOBE\BYPASSNRO` (без кавычек, регистр не важен) | Модифицирует реестр, добавляя кнопку «У меня нет интернета» | Неправильный синтаксис → команда не выполнится |
| **Перезагрузка** | Автоматическая после выполнения команды | Система применяет изменения реестра | Принудительное выключение → повреждение установки |
| **Повторный вход в OOBE** | Дойти до экрана выбора региона снова | После перезагрузки система вернется к OOBE | — |
| **Кнопка «У меня нет интернета»** | Нажать | Появляется только после BYPASSNRO. Позволяет продолжить без сети | Отсутствие кнопки → BYPASSNRO не сработал, повторить |
| **Кнопка «Продолжить ограниченную установку»** | Нажать | Подтверждение локальной установки без Microsoft Account | «Войти с учетной записью Microsoft» → привязка MSA, проблемы при Sysprep |

**⚠️ КРИТИЧНО:** НЕ создавайте пользователя на этом этапе! Мы должны войти в Audit Mode до создания какого-либо профиля.

### ДЕЙСТВИЕ 02.4. Перехват OOBE и вход в Audit Mode

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Экран OOBE** | Экран выбора региона/языка (после обхода BYPASSNRO) | Правильная точка для входа в Audit Mode | Вход после создания пользователя → загрязнение профиля |
| **Комбинация клавиш** | 🔴 `Ctrl + Shift + F3` | Стандартный способ входа в Audit Mode. Запускает `sysprep /audit /reboot` в фоне | Неправильная комбинация → вход в обычный режим OOBE |
| **Интеграция мыши VirtualBox** | Отключить временно (Host Key + I) | Интеграция мыши может перехватывать комбинации клавиш | Комбинация не сработает из-за перехвата хостом |
| **Перезагрузка** | Автоматическая после нажатия комбинации | Система перезагружается в Audit Mode | Принудительное выключение → повреждение |
| **Вход в систему** | Автоматический под встроенным Administrator | Audit Mode использует встроенную учетную запись Administrator без пароля | Запрос пароля → что-то пошло не так, повторить |
| **Рабочий стол** | Появляется с окном «Средство подготовки системы (Sysprep)» | Окно Sysprep Tool — признак успешного входа в Audit Mode | Отсутствие окна → возможно, вход в обычный режим |

**🔄 Альтернативный способ (если Ctrl+Shift+F3 не сработал):**
```cmd
:: Из командной строки (Shift+F10 на экране OOBE):
C:\Windows\System32\Sysprep\sysprep.exe /audit /reboot
```

**⚠️ Почему не создаем пользователя "Admin"?**
Встроенный Administrator в Audit Mode — это **системный** профиль, который:
- Не имеет привязки к AppX-пакетам (в отличие от обычного пользователя)
- Sysprep обрабатывает его корректно при `/generalize`
- Не требует удаления через `unattend.xml` (он не появится в OOBE)

Создание отдельного пользователя "Admin" — это **избыточная операция**, которая:
- Засоряет папку `C:\Users\`
- Требует дополнительного удаления через `FirstLogonCommands`
- Может вызвать рассинхронизацию AppX-пакетов

### ДЕЙСТВИЕ 02.5. Верификация Audit Mode

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Окно Sysprep Tool** | Открыто на рабочем столе | Визуальный признак Audit Mode | Отсутствие → не в Audit Mode |
| **Команда whoami** | `whoami` в CMD → `win11-vm\administrator` | В Audit Mode работаем под встроенным Administrator | Другое имя → возможно, не в Audit Mode |
| **Реестр Setup State** | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Setup\State` = `IMAGE_STATE_UNDEPLOYABLE` | Официальный индикатор Audit Mode | Другое значение → не в Audit Mode |
| **Профиль пользователя** | `C:\Users\` содержит только `Administrator`, `Default`, `Public` | Отсутствие лишних профилей критично для Sysprep | Наличие других профилей → рассинхронизация AppX |
| **Сетевое подключение** | Отсутствует (иконка сети с крестиком) | Подтверждение изоляции | Подключение к сети → риск фоновых обновлений |
| **Окно Sysprep Tool** | НЕ ЗАКРЫВАТЬ, только свернуть | Понадобится для финального запечатывания в Блоке 13 | Закрытие → придется запускать вручную перед Sysprep |

**Команды верификации:**
```cmd
:: Проверка текущего пользователя
whoami

:: Проверка состояния установки через реестр
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Setup\State" /v ImageState

:: Проверка профилей пользователей
dir C:\Users\

:: Проверка сетевых адаптеров
ipconfig /all
```

**Ожидаемый результат верификации:**
- ✅ `whoami` → `win11-vm\administrator` (или `nt authority\system` в некоторых сборках)
- ✅ `ImageState` → `IMAGE_STATE_UNDEPLOYABLE`
- ✅ В `C:\Users\` только `Administrator`, `Default`, `Public`
- ✅ Окно Sysprep Tool открыто
- ✅ Сеть отключена

### ДЕЙСТВИЕ 02.6. Создание снимка ВМ (Clean Audit Mode)

| Параметр | Значение | Обоснование | Риск при ошибке |
|:---|:---|:---|:---|
| **Состояние ВМ** | Работает, в Audit Mode, все проверки пройдены | Правильная точка для снимка | Снимок в неправильном состоянии → бесполезен для отката |
| **Меню VirtualBox** | Машина → Сделать снимок (или Snapshots → Take Snapshot) | Стандартный способ создания снимка | — |
| **Имя снимка** | `02_Clean_Audit_Mode` | Чёткая идентификация точки отката | Непонятное имя → путаница при откате |
| **Описание снимка** | «Чистый Audit Mode после установки Windows, до блокировки служб. Раскладка: EN-US. Сеть: отключена. Guest Additions: НЕ установлены.» | Документирование состояния | Отсутствие описания → непонимание контекста снимка |
| **Время создания** | Фиксируется автоматически | Для хронологии | — |
| **Проверка снимка** | VirtualBox Manager → Snapshots → убедиться, что снимок создан | Подтверждение успешного создания | Отсутствие снимка → нет точки отката |

**Расположение снимка в структуре:**
```
VirtualBox Manager
└── [Имя ВМ]
    └── Snapshots
        ├── 01_Before_OS_Install (из Блока 01)
        └── 02_Clean_Audit_Mode ← ТЕКУЩИЙ СНИМОК
```

**Использование снимка:**
Если на последующих этапах (блокировка служб, удаление AppX) что-то пойдет не так:
1. VirtualBox Manager → Snapshots → выбрать «02_Clean_Audit_Mode»
2. ПКМ → Восстановить (Restore)
3. Подтвердить восстановление
4. ВМ откатится к чистому Audit Mode за 5-10 секунд

## ⚠️ Критические ловушки и их обход

| Ловушка | Симптом | Решение |
|:---|:---|:---|
| **Интеграция мыши VirtualBox перехватывает Ctrl+Shift+F3** | Комбинация не работает, ничего не происходит | Отключить интеграцию мыши: Host Key (правый Ctrl) + I, затем повторить комбинацию |
| **BYPASSNRO не сработал** | После перезагрузки нет кнопки «У меня нет интернета» | Повторить Shift+F10 → `OOBE\BYPASSNRO` → перезагрузка. Проверить раскладку (должна быть ENG) |
| **Создан пользователь до входа в Audit Mode** | В C:\Users\ есть лишний профиль | Откат к снимку «01_Before_OS_Install» и повторная установка |
| **Окно Sysprep Tool закрыто** | Нет визуального признака Audit Mode | Запустить вручную: `C:\Windows\System32\Sysprep\sysprep.exe` |
| **Сеть подключилась автоматически** | Иконка сети активна | Отключить в настройках ВМ: Устройства → Сеть → Сетевой адаптер 1 → Отключить |
| **Команда `OOBE\BYPASSNRO` не работает** | «Не является внутренней или внешней командой» | Проверить раскладку (должна быть ENG). Убедиться, что команда введена без пробелов |
| **Установщик предлагает только "Домашняя" редакция** | Не видно выбор редакции Pro | ISO-образ не содержит редакцию Pro. Использовать официальный образ с Microsoft |
| **После Ctrl+Shift+F3 ВМ просто перезагружается в обычный OOBE** | Audit Mode не активировался | Попробовать альтернативный способ: `sysprep.exe /audit /reboot` из Shift+F10 |

## 📊 Почему встроенный Administrator лучше, чем создание отдельного "Admin"

| Критерий | Встроенный Administrator (Audit Mode) | Отдельный пользователь "Admin" |
|:---|:---|:---|
| **Привязка к AppX** | ❌ Нет привязки | ✅ Есть привязка к пакетам |
| **Sysprep /generalize** | ✅ Обрабатывает корректно | ⚠️ Требует удаления через unattend.xml |
| **Профиль в C:\Users** | ✅ Не создается (только в Audit Mode) | ❌ Создается, требует физического удаления |
| **Рассинхронизация AppX** | ❌ Невозможна | ⚠️ Возможна при обновлениях |
| **Сложность настройки** | ✅ Минимальная | ❌ Требует дополнительных шагов |
| **Риск для Sysprep** | ✅ Минимальный | ⚠️ Повышенный |

**Вывод:** Использование встроенного Administrator в Audit Mode — это **официальный и рекомендованный Microsoft метод** для сборки Golden Image. Создание отдельного пользователя — это избыточная операция, увеличивающая сложность и риски.
