
Для инженера по восстановлению и WTG полезно разделять **не инструменты**, а **уровни абстракции данных**, с которыми работают инструменты.
=====================================================================================================

Если смотреть именно с точки зрения **максимальной универсальности и минимального числа форматов**, то для инженерного комплекта достаточно понимать и активно использовать всего 5 сущностей:

1. **Disk Clone** — быстрый перенос дисков.
2. **System Backup (ADI)** — обычное восстановление Windows.
3. **Disk Image (IMG)** — работа с умирающими накопителями.
4. **VHDX** — Windows To Go, лаборатории, переносимые системы.
5. **WIM** — эталонные и установочные образы Windows.

Эти пять типов покрывают примерно 95% задач ремонта, восстановления, миграции и развертывания ОС.

[MAIN] 📊 **Разбор понятий: Клонирование vs Миграция vs Бэкап**

---

### 1️⃣ КЛОН (Clone) — "Бит-в-бит копия"
**Суть:** Точное посекторное копирование одного диска/раздела на другой. Сохраняется ВСЁ: файловая система, загрузочные сектора, пустое место, удалённые файлы (пока не перезаписаны).

| Параметр | Значение |
|----------|----------|
| **Что копируется** | Все секторы (использованные + свободные) |
| **Размер результата** | = Размер источника (или диска-приёмника) |
| **Восстановление** | Только на диск **того же или большего** размера |
| **Формат файла** | `.IMG`, `.BIN` (raw), либо прямой перенос на диск |
| **Инструменты** | `dd` (Linux), Hasleo Backup → Clone, DiskGenius → Clone Disk |
| **Когда использовать** | Апгрейд HDD → SSD той же ёмкости; криминалистики (сохранение улик); копирование зашифрованных разделов |

⚠️ **Ловушка:** Клон диска 500GB не влезет на диск 480GB, даже если занято всего 20GB.

---

### 2️⃣ МИГРАЦИЯ (System Migration) — "Умный перенос ОС"
**Суть:** Перенос **только живой системы** (ОС + программы + настройки) на другой диск. Пустое место и мусор не копируются. Драйверы и SID **сохраняются** (привязка к старому железу остаётся).

| Параметр | Значение |
|----------|----------|
| **Что копируется** | Только занятые кластеры ОС + загрузчик |
| **Размер результата** | = Размер занятых данных (гибко) |
| **Восстановление** | Работает на дисках **любого размера** (больше занятого) |
| **Формат файла** | Прямой перенос (без промежуточного файла) или `.VHDX` (Fixed) |
| **Инструменты** | Hasleo Backup → System Migration, Macrium Reflect, AOMEI Partition |
| **Когда использовать** | Апгрейд SSD; перенос Windows на новый ПК **той же модели**; создание "родного" VHDX для конкретного ПК |

⚠️ **Ловушка:** Мигрированная система **не загрузится** на другом железе, если не был выполнен `sysprep /generalize`.

---

### 3️⃣ БЕКАП (Backup) — "Архив с возможностью восстановления"
**Суть:** Сжатое/инкрементальное сохранение данных в **проприетарный контейнер**. Поддерживает версии, дедупликацию, шифрование.

| Параметр | Значение |
|----------|----------|
| **Что копируется** | Файлы/разделы/система (на выбор) |
| **Размер результата** | < Размер источника (сжатие) |
| **Восстановление** | На любой диск, выборочно (файл/папка/раздел) |
| **Формат файла** | `.ADI` (Hasleo), `.MRIMG` (Macrium), `.PBI` (Acronis) |
| **Инструменты** | Hasleo Backup, Veeam, Macrium Reflect |
| **Когда использовать** | Регулярное резервирование; точка отката; перенос на диск меньшего размера; восстановление отдельных файлов |

✅ **Главное преимущество:** Инкрементальные/дифференциальные бэкапы (экономия места).

---

### 4️⃣ ОБРАЗ (Image) — "Универсальный контейнер"
**Суть:** Файл-контейнер, содержащий структуру ФС + данные. Бывает **статичным** (ISO/WIM) и **виртуальным диском** (VHDX).

| Тип образа | Назначение | Формат | Пример |
|------------|------------|--------|--------|
| **Загрузочный ISO** | Установка ОС / Live-система | `.ISO` | Windows 11 Setup, Ubuntu Live |
| **WIM (Windows Image)** | Развёртывание Windows (capture/apply) | `.WIM`, `.ESD` | install.wim в ISO Windows |
| **VHDX (Virtual Hard Disk)** | Виртуальная машина / WTG | `.VHDX` | Ваш Windows To Go |
| **Raw Image** | Посекторная копия (для forensics) | `.IMG`, `.BIN` | Клон флешки роутера |

## 🎓 МЕНТОР: КЛЮЧЕВЫЕ ПРИНЦИПЫ

### Принцип 1: "Клон vs Бэкап" — это выбор между скоростью и гибкостью
- **Клон** = быстрее восстанавливать (просто записать на диск), но негибкий (требует диск ≥ источника).
- **Бэкап** = медленнее восстанавливать (распаковка), но гибкий (можно восстановить файл/папку/раздел).

### Принцип 2: "Миграция vs Sysprep" — это выбор между "здесь и сейчас" и "универсальностью"
- **Миграция без sysprep** = работает только на исходном ПК. Быстро, но не универсально.
- **Sysprep /generalize** = сбрасывает SID, драйверы, привязку к железу. Система становится "чистой" и загрузится на любом ПК. **Обязательно для WTG!**

### Принцип 3: "VHDX Fixed vs Dynamic"
- **Fixed** = занимает всё место сразу, но **не фрагментируется**. Критично для WTG (производительность IOPS).
- **Dynamic** = растёт по мере заполнения, но фрагментируется на хостовой ФС. Подходит для тестовых ВМ.

### Принцип 4: "ISO vs WIM vs VHDX"
- **ISO** = дистрибутив для установки (read-only).
- **WIM** = образ для развёртывания через `dism /apply-image` (используется в корпоративном деплое).
- **VHDX** = полноценный виртуальный диск с ОС внутри (WTG, ВМ).

---

## ⚠️ КРИТИЧЕСКИЕ ЛОВУШКИ

1. **Не клонируйте убитый диск на здоровый!** Если диск имеет bad blocks, клонирование может "заразить" новый диск (ошибки файловой системы). Сначала **Raw-клон в .IMG**, потом восстановление из образа.

2. **Не делайте бэкап на тот же диск!** Если диск умирает, бэкап умрёт вместе с ним. Всегда на внешний носитель (P60/SD400).

3. **Sysprep нельзя запускать более 3 раз!** Windows ограничивает количество `sysprep /generalize` на одной установке. Для WTG — создавайте новый VHDX из ISO, а не "гоняйте" одну систему через sysprep.

4. **VHDX на exFAT работает только с Win10 v1809+!** Для старых сборок Windows — только NTFS.

5. **Raw-клон (.IMG) занимает ВСЁ место диска!** Клон диска 1TB = файл 1TB, даже если занято 10GB. Используйте сжатие: `gzip image.img > image.img.gz` (экономия до 70%).

[VALIDATION] ✅ **Чек-лист понимания**
- [ ] Клон = посекторно, бэкап = умно/сжато, миграция = только ОС
- [ ] Для WTG — всегда `sysprep /generalize` + VHDX Fixed
- [ ] Для восстановления убитых дисков — сначала Raw-клон в `.IMG`, потом работа с образом
- [ ] ISO = установочный образ, WIM = корпоративный деплой, VHDX = виртуальный диск
- [ ] Бэкапы — на внешний носитель, никогда на тот же диск

# Клонирование / Миграция / Бэкап — в чём разница

## Концептуальная разница---

## Детальный разбор

### Бэкап (резервное копирование)
**Задача:** сохранить данные/состояние системы в нескольких точках времени, чтобы можно было откатиться.

Ключевые свойства:
- источник продолжает работать во время бэкапа
- хранится отдельно от источника (другой диск, облако, NAS)
- может быть файловым (только данные) или блочным (весь раздел/диск)
- обычно требует инструмента для восстановления — сам по себе не загружается

Типы по охвату: **полный** → **инкрементный** (дельта с предыдущего) → **дифференциальный** (дельта от последнего полного). Для восстановления с убитого накопителя — нужен полный + цепочка инкрементных.

---

### Клонирование
**Задача:** создать точную побитовую копию диска/раздела — готовую к загрузке немедленно.

Ключевые свойства:
- копируются UUID разделов, MBR/GPT, загрузчик, NTFS метаданные — всё
- результат загружается как оригинал, без каких-либо настроек
- `dd`, Clonezilla, Macrium Reflect (clone режим)
- нет истории версий — это «срез сейчас»

Отличие от бэкапа: клон = другой диск с той же системой. Бэкап = архив, из которого надо ещё развернуть.

---

### Миграция
**Задача:** перенести систему на новое железо/другую платформу, при этом адаптировав её.

Форматы: **P2V** (физическая → виртуальная), **V2P** (обратно), **V2V** (Hyper-V → VMware и т.п.), **P2P** (замена сервера). Исходная машина после миграции обычно выводится из роли — это не копия, а переезд.

---

## Образы — классификация

### По структуре содержимого

| Тип | Что внутри | Когда нужен |
|---|---|---|
| Посекторный (raw/dd) | Каждый бит, включая пустое место | Форензика, максимальная совместимость |
| Файловый (WIM, tar) | Только реальные файлы | Windows install.wim, резервные копии данных |
| Блочный сжатый | Занятые блоки + сжатие | Clonezilla, Macrium .mrimg |
| VHDX/VHD/VMDK | Виртуальный диск, монтируется напрямую | Hyper-V, универсальные, легко подключить |
| EWF/E01 | Форензический, с хэшами и метаданными | Расследования, доказательная база |

### По назначению при загрузке

**Загрузочный ISO** — содержит и ОС/среду (WinPE, Linux live), и файлы установки/восстановления. Пишется на USB/DVD, грузится на голом железе.

**Установочный образ** — `install.wim` / `install.esd` внутри ISO. Разворачивается Windows Setup или DISM. Может быть мультиизданиевым.

**WinRE / rescue среда** — минимальная среда для починки загрузчика, восстановления из бэкапа, работы с дисками. Живёт в скрытом разделе или на отдельном носителе.

**Образ восстановления системы** (System Image, Acronis .tib, Macrium .mrimg) — снапшот раздела/диска, раскатывается через среду восстановления.

---

## VHDX — отдельно

VHDX — это виртуальный жёсткий диск (контейнер). Форматы:

- **Fixed** — фиксированный размер, максимальная скорость
- **Dynamic** — растёт по мере заполнения, экономит место
- **Differencing** — хранит только отличия от родительского VHDX (для снапшотов Hyper-V)

Универсальность VHDX в том, что Windows умеет: монтировать как обычный диск в проводнике, **загружаться прямо с него** (VHD Boot — `bcdedit`), разворачивать через DISM, использовать как диск ВМ. Это делает VHDX отличным форматом и для бэкапа системы, и для шаблонов ВМ, и для тестовых сред.

---

## Что выбирать под задачи

**Восстановление с убитого накопителя →** форензический образ (dd/E01) с другой машины пока диск ещё читается + Clonezilla/ddrescue для битых секторов.

**Быстрый откат системы →** VHDX-снапшот (Hyper-V) или точка восстановления + полный образ системы на внешнем диске.

**Переезд на новый диск →** клон (Macrium Reflect clone, Clonezilla). Результат загружается сразу.

**Шаблон для разворота нескольких машин →** VHDX/VMDK + sysprep, или WIM с answer file.

**Загрузочная флешка для ремонта →** ISO с WinPE/Linux live + необходимыми утилитами.
