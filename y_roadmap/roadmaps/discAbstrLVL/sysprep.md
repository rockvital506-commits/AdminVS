[MAIN] 📋 **Sysprep /generalize — лимит 3 запусков: подробный разбор**

---

## 🔧 ЧТО ТАКОЕ SYSPREP И ЗАЧЕМ ОН НУЖЕН

**Sysprep (System Preparation Tool)** — утилита Microsoft для подготовки образа Windows к клонированию/развёртыванию.

### Режим `/generalize` выполняет:
1. **Удаление уникальных идентификаторов:**
   - SID (Security Identifier) машины
   - SID пользователя
   - Имя компьютера
   - Продукт ID (частично)

2. **Сброс драйверов:**
   - Удаление драйверов, специфичных для конкретного железа
   - Сохранение только универсальных ( Inbox Drivers )

3. **Очистка системы:**
   - Сброс активации Windows (требуется повторная)
   - Удаление точек восстановления
   - Очистка журналов событий
   - Сброс настроек сети

4. **Подготовка к OOBE (Out-of-Box Experience):**
   - При следующем запуске система ведёт себя как " freshly installed "
   - Запрашивает регион, язык, учётную запись

---

## ⚠️ ПОЧЕМУ ЛИМИТ В 3 РАЗА?

### Техническая причина: **Rearm Count**

Windows имеет механизм **SLIC (Software Licensing Internal Code)**, который отслеживает количество "переустановок" без активации.

**Ключ реестра:**
```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform\SkipRearm
```

- **Значение по умолчанию:** `0`
- **Максимальное значение:** `3` (для Windows 10/11)
- **Каждый `sysprep /generalize`** уменьшает `Rearm Count` на 1

### Как это работает:

| Запуск sysprep | SkipRearm | Состояние системы |
|----------------|-----------|-------------------|
| Исходная установка | 3 | ✅ OK |
| 1-й generalize | 2 | ✅ OK |
| 2-й generalize | 1 | ✅ OK |
| 3-й generalize | 0 | ✅ OK |
| 4-й generalize | -1 | ❌ **ОШИБКА** |

---

## 💥 ЧТО ПРОИСХОДИТ ПРИ ПРЕВЫШЕНИИ ЛИМИТА?

### Симптомы:

**1. Sysprep завершается с ошибкой:**
```
[SYSPRP] Sysprep has been run too many times on this machine.
Sysprep is limited to run 3 times. Please use a new installation.
```

**2. Система перестаёт загружаться:**
- BSOD `0xC0000142` (STATUS_INITIALIZATION_FAILED)
- Циклическая перезагрузка на этапе OOBE
- "Windows could not complete the installation"

**3. Невозможность активации:**
- SLIC-счётчик исчерпан
- Требуется чистая переустановка

## 🛠️ КАК ПРОВЕРИТЬ ОСТАТОК SYSPREP?

### Метод 1: Реестр (на работающей системе)
```powershell
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform" | Select-Object SkipRearm
```

### Метод 2: Командная строка (WinPE)
```cmd
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform" /v SkipRearm
```

### Метод 3: PowerShell (полная информация)
```powershell
# Проверка оставшихся запусков sysprep
$rearm = (Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform").SkipRearm
Write-Host "Осталось запусков sysprep: $rearm" -ForegroundColor $(if($rearm -gt 0){"Green"}else{"Red"})
```

## 🎯 ПРАВИЛЬНАЯ СТРАТЕГИЯ СОЗДАНИЯ WTG

### ❌ НЕПРАВИЛЬНО (ведёт к исчерпанию лимита):
```
1. Установить Win11 на VHDX
2. Настроить софт
3. sysprep /generalize
4. Запустить WTG, обновить драйверы
5. sysprep /generalize (2-й раз)
6. Снова запустить, что-то поменять
7. sysprep /generalize (3-й раз) ← КРИТИЧЕСКАЯ ОШИБКА
```

### ✅ ПРАВИЛЬНО (бесконечное использование):

#### **Метод A: "Золотой образ" (рекомендуемый)**

```
1. Создать ЧИСТЫЙ VHDX из ISO (один раз)
   └── Hasleo Backup → System Clone → Export to VHDX
   └── Имя: Win11_Base_Clean.vhdx

2. Смонтировать VHDX, установить софт
   └── Установить: Office, Drivers, Tools
   └── НЕ запускать sysprep!

3. Создать копию: Win11_Full_Config.vhdx
   └── FreeFileSync или Hasleo Clone

4. Для WTG:
   ├── Загрузиться с Win11_Full_Config.vhdx
   ├── sysprep /generalize /oobe /shutdown
   └── Переименовать в: Win11_WTG_Universal.vhdx

5. Если нужно обновить WTG:
   ├── НЕ трогать Win11_WTG_Universal.vhdx
   ├── Взять Win11_Full_Config.vhdx
   ├── Обновить софт
   ├── sysprep /generalize
   └── Заменить Win11_WTG_Universal.vhdx
```

**Преимущество:** У вас всегда есть "золотой образ" без sysprep, который можно клонировать бесконечно.

---

#### **Метод B: "Дифференциальные диски" (продвинутый)**

```
1. Создать базовый VHDX (Read-Only):
   └── Win11_Base.vhdx (Fixed, 64GB)
   └── Никогда не запускать sysprep на нём!

2. Создать дифференциальный диск:
   └── Win11_WTG_Diff.vhdx (Dynamic)
   └── Parent: Win11_Base.vhdx

3. Все изменения пишутся в Diff-диск
4. При необходимости:
   ├── Удалить Win11_WTG_Diff.vhdx
   └── Создать новый Diff-диск
```

**Команда PowerShell:**
```powershell
# Создание дифференциального VHDX
New-VHD -Path "D:\WTG\Win11_Diff.vhdx" `
        -ParentPath "D:\WTG\Win11_Base.vhdx" `
        -Differencing
```

---

#### **Метод C: "Свежая установка каждый раз" (для инженеров)**

```
1. Хранить чистые ISO Windows
2. При необходимости нового WTG:
   ├── Загрузиться с WinPE (Strelec)
   ├── Создать новый VHDX из ISO
   │   └── Hasleo → Deploy from ISO
   ├── Установить минимальный софт
   └── sysprep /generalize (1 раз!)
```

**Автоматизация через скрипт:**
```powershell
# Create_WTG.ps1
param(
    [string]$ISOPath = "D:\ISO\Win11_24H2.iso",
    [string]$VHDXPath = "D:\WTG\Win11_WTG_New.vhdx"
)

# 1. Смонтировать ISO
$disk = Mount-DiskImage -ImagePath $ISOPath -PassThru
$drive = (Get-Volume -DiskImage $disk).DriveLetter

# 2. Создать VHDX
New-VHD -Path $VHDXPath -SizeBytes 64GB -Dynamic

# 3. Развернуть образ
Apply-WindowsImage -ImagePath "$($drive):\sources\install.wim" `
                   -Index 1 `
                   -Path "E:\" `
                   -VHDPath $VHDXPath

# 4. Запустить sysprep
Start-Process -FilePath "E:\Windows\System32\Sysprep\sysprep.exe" `
              -ArgumentList "/generalize /oobe /shutdown /mode:vm" `
              -Wait

# 5. Размонтировать ISO
Dismount-DiskImage -ImagePath $ISOPath
```

## 🔁 КАК СБРОСИТЬ СЧЁТЧИК SYSPREP? (ОБХОДНОЙ ПУТЬ)

⚠️ **Внимание:** Это нарушает лицензионное соглашение Microsoft! Используйте только для тестовых/инженерных целей.

### Метод 1: Правка реестра (временное решение)
```powershell
# Увеличение SkipRearm до 8 (максимум)
Set-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform\SkipRearm" -Value 8

# Перезагрузка обязательна
Restart-Computer
```

**Недостаток:** После 3-го sysprep система всё равно может выдать ошибку.

---

### Метод 2: Сброс через slmgr (более надёжный)
```cmd
:: Запустить от Администратора
slmgr /rearm

:: Проверка
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform" /v SkipRearm
```

**Результат:** Счётчик возвращается к `3`.

**Ограничение:** Можно выполнить не более **8 раз** на одной установке (архитектурное ограничение SLIC).

---

### Метод 3: "Чистая установка из ISO" (гарантированный)
```
1. Смонтировать ISO
2. Запустить setup.exe
3. Выбрать "Сохранить файлы и приложения"
4. После обновления счётчик сбрасывается
```

## 📊 СРАВНЕНИЕ МЕТОДОВ СОЗДАНИЯ WTG

| Метод | Сложность | Лимит sysprep | Размер VHDX | Гибкость | Рекомендация |
|-------|-----------|---------------|-------------|----------|--------------|
| **Прямой sysprep** | Низкая | 3 раза | 30-40 GB | Низкая | ❌ Не использовать |
| **Золотой образ** | Средняя | ∞ (через клонирование) | 40-60 GB | Высокая | ✅ **Рекомендуется** |
| **Дифференциальный** | Высокая | ∞ | 10-20 GB (dynamic) | Средняя | ⚠️ Для тестов |
| **Свежая установка** | Средняя | ∞ (каждый раз новый) | 30 GB | Высокая | ✅ Для инженеров |

## 🎓 МЕНТОР: ПРАКТИЧЕСКИЕ СОВЕТЫ

### 1. **Всегда храните "чистый" образ**
```
D:\WTG\
├── Base\
│   └── Win11_Clean_24H2.vhdx    ← НИКОГДА не sysprep!
├── Configured\
│   └── Win11_Full_Tools.vhdx    ← Установлен софт
└── Universal\
    └── Win11_WTG_Ready.vhdx     ← После sysprep
```

### 2. **Документируйте количество sysprep**
Создайте файл `sysprep_log.txt` в папке с VHDX:
```
Win11_WTG_Ready.vhdx
- 2026-06-01: 1-й sysprep (initial setup)
- 2026-06-05: 2-й sysprep (added drivers)
- Осталось: 1 запуск
```

### 3. **Используйте Hasleo Backup для клонирования**
```
Hasleo → System Clone → Export to VHDX
```
Это создаёт копию БЕЗ уменьшения счётчика sysprep.

### 4. **Проверяйте счётчик перед sysprep**
```powershell
# Добавить в автозагрузку WTG
$rearm = (Get-ItemProperty "HKLM:\...\SoftwareProtectionPlatform").SkipRearm
if ($rearm -eq 0) {
    Write-Warning "ВНИМАНИЕ: Лимит sysprep исчерпан!"
    Write-Host "Создайте новый VHDX из ISO" -ForegroundColor Red
}
```

## ✅ ЧЕК-ЛИСТ: Безопасное создание WTG

- [ ] Создан "золотой образ" без sysprep (`Win11_Base.vhdx`)
- [ ] Установлен софт на копию золотого образа
- [ ] Проверен счётчик `SkipRearm` (≥1)
- [ ] Выполнен `sysprep /generalize /oobe /shutdown`
- [ ] Создана резервная копия VHDX перед sysprep
- [ ] Задокументировано количество запусков sysprep
- [ ] VHDX протестирован на загрузку (UEFI + Legacy)

---

**Итог:** Лимит в 3 запуска — это архитектурное ограничение Windows, а не баг. Правильная стратегия — **хранить "золотой образ"** и клонировать его, а не "гонять" одну систему через многократный sysprep. Для инженерной сборки это критично, так как вы будете регулярно обновлять WTG.

Как подготовить Windows через sysprep перед переносом на чужой ПК?
=====================================================================================================
Подготовка Windows с помощью утилиты sysprep (System Preparation Tool) удаляет уникальные идентификаторы (SID) системы, сбрасывает активацию (допускается до 3 раз) и очищает привязку к процессору, чипсету и контроллерам дисков (AHCI/NVMe). После этого система запустится на любом другом железе.
## ⚠️ Важные правила перед стартом

* Сделайте бэкап: перед запуском sysprep обязательно сделайте резервную копию в Rescuezilla. Если утилита завершится с ошибкой, система может перестать загружаться.
* Удалите лишних пользователей: если на ПК есть временные учетные записи, удалите их.
* Отключите шифрование: BitLocker должен быть полностью выключен.

------------------------------
## Пошаговый алгоритм подготовки## Шаг 1: Очистка системы (Рекомендуется)

   1. Нажмите Win + R, введите cleanmgr и очистите системный диск от временных файлов.
   2. Отключите сторонние антивирусы (они часто блокируют работу sysprep).

## Шаг 2: Запуск Sysprep

   1. Нажмите Win + R, введите sysprep и нажмите Enter. Откроется папка C:\Windows\System32\sysprep.
   2. Запустите файл sysprep.exe от имени администратора.
   3. В появившемся окне выставите следующие настройки:
   * Действие по очистке системы: выберите Переход в режим приветствия системы (OOBE).
      * Обязательно поставьте галочку Подготовка к использованию (Generalize). Это самый важный пункт, который стирает привязку к железу.
      * Параметры завершения работы: выберите Завершение работы.
   4. Нажмите ОК.

Система выполнит очистку (это занимает от 1 до 5 минут) и компьютер выключится.
## Шаг 3: Создание слепка в Rescuezilla

   1. Не включайте ПК в обычном режиме! Если Windows начнет загружаться, процедуру sysprep придется делать заново.
   2. Вставьте флешку с Ventoy, включите ПК и сразу зайдите в Boot Menu.
   3. Загрузите Rescuezilla через Ventoy.
   4. Сделайте бэкап диска стандартным способом. Этот образ теперь является универсальным.

## Шаг 4: Развертывание на чужом ПК

   1. На чужом ПК загрузитесь с Rescuezilla и восстановите созданный образ.
   2. После успешного восстановления извлеките флешку и включите ПК.
   3. Windows начнет первичную настройку (этап OOBE): устройство заново опросит новое железо, установит стандартные драйверы, предложит выбрать регион, язык и создать нового пользователя.

------------------------------
## 🛠️ Возможные проблемы и их решение
Если в процессе работы sysprep возникла ошибка, программа выдаст сообщение: "Программа Sysprep не смогла проверить установленную копию Windows".
В 99% случаев в Windows 10/11 это связано со встроенными приложениями из Microsoft Store (UWP-пакетами), которые обновились для текущего пользователя, но не обновились для остальных профилей.
Как исправить:

   1. Откройте файл лога ошибки: C:\Windows\System32\Sysprep\Panther\setupact.log.
   2. Прокрутите в самый низ и найдите строчку, где указано имя проблемного пакета (например, AdobeNotificationClient или StateRepository).
   3. Откройте PowerShell от имени администратора и удалите этот пакет командой:
   Remove-AppxPackage -Package "ПОЛНОЕ_ИМЯ_ПАКЕТА_ИЗ_ЛОГА"
   4. После этого запустите sysprep заново.

Если вы хотите автоматизировать процесс (например, чтобы при первом запуске на чужом ПК не создавался новый пользователь, а оставался старый), для этого потребуется использовать файл ответов unattend.xml.
Если вам интересен такой вариант, дайте знать — я пришлю шаблон файла ответов и объясню, куда его положить перед запуском утилиты.
