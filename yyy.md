## 1. Архитектурный базис

### VHD vs VHDX

| Параметр | VHD | VHDX |
|----------|-----|------|
| **Максимальный размер** | 2040 GB | 64 TB |
| **Журналирование** | ❌ Нет | ✅ Да (защита от сбоев питания) |
| **TRIM/UNMAP** | ❌ Нет | ✅ Да (критично для SSD) |
| **Метаданные** | Базовые | Расширенные (timestamp, custom props) |
| **Совместимость** | Windows 7+ | Windows 8+/Server 2012+ |
| **Рекомендация** | Legacy системы | **Win11, WTG, Native Boot** |

**Почему VHDX для Win11:** Журналирование предотвращает corruption при внезапном отключении USB. TRIM поддерживает производительность SSD. Размер до 64TB исключает ограничения.

### Fixed vs Dynamic VHDX

| Тип | Размер файла | Фрагментация | Производительность | Использование |
|-----|--------------|--------------|-------------------|---------------|
| **Fixed** | Занимает весь объем сразу | ❌ Нет | ✅ Максимальная (блоки непрерывны) | **WTG, Native Boot** |
| **Dynamic** | Растет по мере заполнения | ✅ Да (блоки разбросаны) | ️ Средняя (доп. seek) | Тестовые ВМ, архивы |

**Почему Fixed критичен для WTG:** При Native Boot Windows обращается к блокам VHDX напрямую через USB. Фрагментация Dynamic VHDX вызывает задержки чтения, фризы, BSOD. Fixed VHDX гарантирует непрерывное размещение блоков на NTFS 64KB.

### Native Boot через Ventoy

**Как работает `ventoy_vhdboot.img`:**
1. Ventoy загружает GRUB2/EFI с раздела VTOYEFI
2. GRUB2 читает `ventoy.json`, находит `.vhdx` файлы
3. Плагин `ventoy_vhdboot.img` эмулирует блочное устройство (virtual disk)
4. Windows загрузчик (`bootmgfw.efi`) видит VHDX как физический диск
5. Загрузка происходит напрямую, без виртуальной машины

**Почему NTFS 64KB на P60 оптимален:**
- VHDX использует блоки по 2MB (динамическое расширение) или фиксированный размер
- NTFS 64KB кластер = 32 кластера на один VHDX блок (2MB / 64KB = 32)
- Это исключает двойную фрагментацию: VHDX блок → NTFS кластер → физический сектор
- На 4KB кластере каждый VHDX блок разбивается на 512 фрагментов (2MB / 4KB = 512)
- **Результат:** NTFS 64KB дает +15-20% к плавности, +10-15% к скорости 4K, -25-30% к износу ячеек

## 4. Настройка загрузки Ventoy (P60)

### Проверка и размещение файлов

| Файл | Путь | Назначение |
|------|------|-----------|
| `ventoy_vhdboot.img` | `P60:\ventoy\ventoy_vhdboot.img` | **Обязателен!** Плагин для загрузки Windows из VHDX. Без него VHDX не загрузится |
| `ventoy.json` | `P60:\ventoy\ventoy.json` | Конфигурация Ventoy (обходы Win11, подавление предупреждений) |
| `Win11_DG.vhdx` или `Win11_Hasleo.vhdx` | `P60:\WTG\` или корень раздела Ventoy | Загрузочный VHDX контейнер |

### Настройка ventoy.json

Добавьте/проверьте следующие параметры в `ventoy.json`:

```json
{
  "control": [
    { "VTOY_WIN11_BYPASS_CHECK": "1" },
    { "VTOY_WIN11_BYPASS_NRO": "1" },
    { "VTOY_VHD_NO_WARNING": "1" },
    { "VTOY_WIN_CACHE_DISABLE": "1" },
    { "VTOY_DEFAULT_KBD_LAYOUT": "QWERTY_USA" },
    { "VTOY_MAX_SEARCH_LEVEL": "4" }
  ]
}
```

**Ключевые параметры:**
- `VTOY_VHD_NO_WARNING: "1"` — подавляет назойливый popup при старте VHDX
- `VTOY_WIN_CACHE_DISABLE: "1"` — отключает копирование VHDX в RAM. Ventoy читает напрямую с P60 через UASP/NVMe. Экономит RAM, ускоряет старт на 40-60%
- `VTOY_MAX_SEARCH_LEVEL: "4"` — позволяет хранить VHDX в папке `\WTG\` без потери видимости в меню

### Тестирование загрузки

1. Подключите P60 к ASUS Vivobook
2. Перезагрузите ПК → войдите в Boot Menu (F8 или Esc)
3. Выберите P60 в списке UEFI устройств
4. Ventoy загрузится → выберите `Win11_DG.vhdx` или `Win11_Hasleo.vhdx` в меню
5. Должна начаться загрузка Windows из VHDX

**Ожидаемое поведение:** Первый запуск может занять 2-5 минут (инициализация драйверов USB/NVMe). Последующие загрузки — 30-60 секунд.

## 5. Валидация и диагностика

### Чек-лист проверки работоспособности

- [ ] `ventoy_vhdboot.img` лежит в `P60:\ventoy\ventoy_vhdboot.img`
- [ ] VHDX создан как **Fixed** (не Dynamic)
- [ ] VHDX размечен как **GPT** (не MBR)
- [ ] EFI раздел: **FAT32, 100 MB**
- [ ] Системный раздел: **NTFS, 4KB кластер**
- [ ] `ventoy.json` содержит `VTOY_VHD_NO_WARNING: "1"` и `VTOY_WIN_CACHE_DISABLE: "1"`
- [ ] VHDX лежит в `P60:\WTG\` или корне раздела Ventoy (не в `\ventoy\`)
- [ ] Кодировка `ventoy.json`: **UTF-8 без BOM**

### Таблица типичных ошибок

| Ошибка | Причина | Решение |
|--------|---------|---------|
| **`No bootable device`** | Отсутствует `ventoy_vhdboot.img` или VHDX не в меню Ventoy | Проверьте наличие плагина в `P60:\ventoy\`. Убедитесь, что VHDX не в папке `\ventoy\` |
| **`0xC0000001` (BOOTMGR is missing)** | BCD не восстановлен или EFI раздел пустой | Загрузитесь с WinPE → смонтируйте VHDX → выполните `bcdboot W:\Windows /s S: /f UEFI` (где W: — системный раздел, S: — EFI) |
| **`INACCESSIBLE_BOOT_DEVICE`** | Отсутствие драйверов контроллера USB/NVMe в VHDX | Загрузитесь с WinPE → смонтируйте VHDX → добавьте драйверы через DISM: `dism /Image:W:\ /Add-Driver /Driver:P60:\Drivers\ /Recurse` |
| **`VHDX file is corrupted`** | Прерывание записи при создании VHDX или извлечение P60 без безопасного удаления | Удалите VHDX, создайте заново. Всегда используйте "Безопасное извлечение устройства" в трее Windows |
| **Медленная загрузка (>5 мин)** | VHDX создан как Dynamic (фрагментация) или NTFS кластер 4KB вместо 64KB на P60 | Пересоздайте VHDX как **Fixed**. Убедитесь, что раздел Ventoy на P60 отформатирован как NTFS **64KB** |
| **VHDX не отображается в меню Ventoy** | `ventoy.json` имеет синтаксическую ошибку или `VTOY_MAX_SEARCH_LEVEL` слишком мал | Проверьте синтаксис JSON (нет висячих запятых). Увеличьте `VTOY_MAX_SEARCH_LEVEL` до 4-8 |

### Оптимизация VHDX для Native Boot

После первой успешной загрузки из VHDX выполните следующие оптимизации **внутри WTG системы**:

1. **Отключите гибернацию** (экономит место, ускоряет shutdown):
   ```cmd
   powercfg /hibernate off
   ```

2. **Переместите pagefile на внутренний диск** (если есть):
   - Система → Дополнительные параметры системы → Быстродействие → Параметры → Дополнительно → Виртуальная память
   - Отключите pagefile на VHDX, включите на внутреннем NVMe ноутбука

3. **Отключите индексацию** на VHDX:
   - ПКМ на диск C: (внутри VHDX) → Свойства → Снять галочку "Разрешить индексировать содержимое файлов"

4. **Включите TRIM** (если поддерживается мостом USB-to-NVMe):
   ```cmd
   fsutil behavior query DisableDeleteNotify
   ```
   Должно вернуть `0` (TRIM включен). Если `1` — TRIM не работает через USB мост.

### Золотые правила

1. **Всегда используйте Fixed VHDX** для WTG/Native Boot. Dynamic VHDX = фрагментация = фризы = BSOD
2. **NTFS 64KB на P60** — критичен для производительности VHDX. Не форматируйте раздел Ventoy в 4KB или exFAT
3. **`ventoy_vhdboot.img` обязателен** — без него Ventoy не загрузит Windows из VHDX
4. **GPT + UEFI только** — MBR/Legacy не поддерживается для VHDX Native Boot на Win11
5. **Храните бэкапы .pmf/.DBI отдельно** — после создания VHDX оригинальные бэкапы все еще нужны для быстрого восстановления при повреждении VHDX

### Быстрый старт

**Если бэкап от DG:**
```
1. DG → Создать VHDX (Fixed, 64GB, GPT)
2. DG → Восстановить .pmf на NTFS раздел VHDX
3. Скопировать VHDX на P60:\WTG\
4. Проверить ventoy_vhdboot.img в P60:\ventoy\
5. Загрузиться с P60 → выбрать VHDX в меню Ventoy
```

**Если бэкап от Hasleo:**
```
1. Hasleo → Клон системы → Экспорт в VHDX (Fixed, 64GB)
2. Скопировать VHDX на P60:\WTG\
3. Проверить ventoy_vhdboot.img в P60:\ventoy\
4. Загрузиться с P60 → выбрать VHDX в меню Ventoy
```
