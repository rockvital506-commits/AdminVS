[MAIN] 📄 **Итоговая Синтезированная Карта: Полный жизненный цикл Golden Image Windows 10/11**

Ниже представлена финальная, выверенная структура мануала. Она объединяет **полный жизненный цикл** (от создания ВМ до захвата WIM) с **глубокими инженерными решениями** (Hot-Plug VDI, двухфазная блокировка, удаление Bloatware в самом конце).

---

### БЛОК 0. PRE-FLIGHT: Подготовка на хосте (до запуска ВМ)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Подготовка всех offline-артефактов и Hot-Plug диска на хост-машине до первого запуска ВМ |
| **Почему №0** | ВМ изолирована от интернета. Все пакеты, драйверы, скрипты и утилиты должны быть физически доступны через Hot-Plug диск до начала работы |
| **Критичность** | 🔴 **Блокирующая** — без этого блока все последующие блоки невозможны |
| **Где выполняется** | Хост-ОС (Win11 Vivobook), не внутри ВМ |

**Подблоки Б00:**

| № | Подблок | Что делает | Что подготавливается | Риск при пропуске |
|:---|:---|:---|:---|:---|
| 0.1 | **Скачивание offline-обновлений (MSU/CAB)** | Загрузка SSU, LCU, .NET Framework | Файлы `.msu`, `.cab` в папке `HotPlug:\Updates\` | Sysprep на устаревшей сборке может иметь известные баги |
| 0.2 | **Скачивание пакетов драйверов** | Загрузка универсальных драйверов (NVMe, USB 3.x, Intel RST/VMD, LAN/WLAN) | Папки с `.inf` в `HotPlug:\Drivers\` | Целевой ПК не загрузится после деплоя без критичных драйверов хранилища |
| 0.3 | **Подготовка скриптов автоматизации** | Копирование PowerShell/CMD скриптов (complete_cleaner.ps1, clean_hkcu.ps1 и др.) | `HotPlug:\Scripts\` | Ручное выполнение = человеческий фактор = нестабильный образ |
| 0.4 | **Подготовка портативного ПО** | Копирование установщиков (silent/unattended) и портативных утилит | `HotPlug:\Software\` | Невозможность установить нужный софт в изолированной среде |
| 0.5 | **Создание Hot-Plug VDI диска** | Создание виртуального диска 20-40 ГБ, форматирование NTFS, включение флага Hot-Pluggable | `HotPlug.vdi`, примонтирован как SATA порт 1 | Нет механизма передачи файлов в изолированную ВМ |

| **Почему №1** | Все дальнейшие манипуляции происходят внутри этой ВМ. Ошибки на этом этапе (например, Shared Folder) приведут к загрязнению PnP-дерева |
| **Критичность** | 🔴 **Блокирующая** |

| 1.5 | **Снимок ВМ** | Создание точки отката | Имя: "Before OS Install" | Точка быстрого сброса при ошибке установки ОС. |

### БЛОК 3A. ПЕРВИЧНАЯ БЛОКИРОВКА ФОНОВОЙ АКТИВНОСТИ (Audit Mode)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Мгновенное подавление всех служб и процессов, которые могут модифицировать систему в фоне |
| **Почему №3A** | Должен выполняться СРАЗУ после входа в Audit Mode. Если Windows Update или Store успеет обновить AppX-пакет — Sysprep упадет |
| **Критичность** | 🔴 **Блокирующая для Sysprep** |

**Подблоки Б03A:**

| № | Подблок | Что блокируется / останавливается | Метод | Риск при пропуске |
|:---|:---|:---|:---|:---|
| 3A.1 | **Вход в Audit Mode** | Переход в сервисный режим | `Ctrl+Shift+F3` на экране OOBE | Активирует встроенный Administrator без создания пользовательского профиля. |
| 3A.2 | **Службы Windows Update** | `wuauserv`, `UsoSvc`, `WaaSMedicSvc`, `dosvc`, `BITS` | `sc config` + `Set-Service` → Disabled | Фон. загрузка обновлений → изменение состояния AppX → Sysprep crash. |
| 3A.3 | **Microsoft Store / CloudContent** | `InstallService`, `AppXSvc`, `ClipSVC` | `Set-Service` → Disabled | Store может самообновить provisioned packages. |
| 3A.4 | **Диагностическая телеметрия** | `DiagTrack`, `dmwappushservice`, `WerSvc` | `Set-Service` → Disabled | Фоновая активность, запись логов, потребление I/O. |
| 3A.5 | **Критичные задачи планировщика** | `\Microsoft\Windows\WindowsUpdate\*`, `\Setup\*` | `schtasks /Change /Disable` | Фоновые триггеры могут запустить обновление в неподходящий момент. |

### БЛОК 4. OFFLINE-ОБНОВЛЕНИЕ СИСТЕМЫ (DISM Servicing)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Установка всех кумулятивных обновлений, SSU, .NET Framework в образ без интернета |
| **Почему №4** | Обновления ставятся ПОСЛЕ блокировки (Б03A), чтобы служба WU не вмешивалась. ДО установки ПО (Б06), чтобы обновления не были перезаписаны инсталляторами |
| **Критичность** | 🟡 **Высокая** |

**Подблоки Б04:**

| № | Подблок | Что делает | Механизм | Зависимости |
|:---|:---|:---|:---|:---|
| 4.1 | **Монтирование Hot-Plug диска** | Подключение виртуального диска через меню VirtualBox → Устройства → Жесткие диски | SATA Hot-Plug | Б00.5 |
| 4.2 | **Установка Servicing Stack Update (SSU)** | Установка стека обслуживания ПЕРВЫМ | `DISM /Online /Add-Package /PackagePath:SSU-*.cab` | Б00.1 |
| 4.3 | **Установка кумулятивного обновления (LCU)** | Установка последнего Cumulative Update | `DISM /Online /Add-Package /PackagePath:windows11.0-kb*.msu` | 4.2 (SSU должен быть установлен первым) |
| 4.4 | **Установка .NET Framework Update** | Обновление .NET 3.5/4.8.x | `DISM /Online /Add-Package` | 4.2 |
| 4.5 | **Перезагрузка и верификация** | Проверка статуса пакетов | `shutdown /r /t 0` → `DISM /Online /Get-Packages \| findstr Installed` | Гарантия, что нет pending-пакетов, которые сломают Sysprep. |

### БЛОК 5. ИНТЕГРАЦИЯ ДРАЙВЕРОВ (Driver Store Injection)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Добавление универсальных драйверов в Driver Store образа для гарантированного старта на любом целевом железе |
| **Почему №5** | ПОСЛЕ обновлений (Б04), потому что CU может обновить inbox-драйверы. Интеграция после CU гарантирует, что наши драйверы не перезапишутся |
| **Критичность** | 🟡 **Высокая** |

**Подблоки Б05:**

| № | Подблок | Что делает | Драйверы | Зависимости |
|:---|:---|:---|:---|:---|
| 5.1 | **Интеграция драйверов хранилища** | Критично: без них целевой ПК не увидит системный диск | Intel RST/VMD, Samsung NVMe, Intel RST VMD Controller | Б00.2 |
| 5.2 | **Интеграция сетевых драйверов** | Гарантия наличия сети после деплоя | Intel I219/I225/I226, Realtek RTL8125/8111, Intel Wi-Fi 6/6E/7 | Б00.2 |
| 5.3 | **Интеграция USB/Chipset драйверов** | Корректная работа периферии | Intel USB 3.x, AMD USB 3.1, Intel Chipset INF | Б00.2 |
| 5.4 | **Верификация Driver Store** | Проверка, что драйверы добавлены без конфликтов | `DISM /Online /Get-Drivers` → проверка списка | — |

### БЛОК 3B. ПОВТОРНАЯ БЛОКИРОВКА И УДАЛЕНИЕ ВОССТАНОВЛЕННЫХ UWP

| **Почему №3B** | ПОСЛЕ установки ПО (Б06), потому что инсталляторы могли восстановить службы и UWP-зависимости. ДО финального удаления Bloatware (Б07) |
| **Критичность** | 🔴 **Блокирующая для Sysprep** |

### БЛОК 7. УДАЛЕНИЕ BLOATWARE И APPX-ПАКЕТОВ

| Параметр | Значение |
|:---|:---|
| **Назначение** | Полное удаление всех предустановленных UWP/AppX приложений + Win32 мусора |
| **Почему №7** | ПОСЛЕ установки ПО (Б06) и повторной блокировки (Б03B). Sysprep требует, чтобы у ВСЕХ пользователей не было AppX-пакетов, которых нет у других |
| **Критичность** | 🔴 **Блокирующая для Sysprep** |

**Подблоки Б07:**

| № | Подблок | Что делает | Полный список удаляемых сущностей | Риск при пропуске |
|:---|:---|:---|:---|:---|
| 7.1 | **Удаление Provisioned AppX** | Удаляет пакеты из образа так, что они не появятся при создании новых профилей | Xbox*, Bing*, Zune*, People, Skype, OfficeHub, Solitaire, FeedbackHub, MixedReality, Widgets, Copilot, DevHome | Новые пользователи получат мусорные приложения |
| 7.2 | **Удаление установленных AppX** | Удаляет пакеты из текущего профиля | Те же пакеты + `Get-AppxPackage -AllUsers \| Remove-AppxPackage` | Sysprep увидит пакеты у Admin, которых нет у Default User → crash |
| 7.3 | **Удаление Win32 bloatware** | Тихое удаление предустановленных Win32-программ через реестр Uninstall | OEM-утилиты, trial-версии, рекламное ПО | Занимают место, замедляют старт, могут конфликтовать |
| 7.4 | **Блокировка восстановления bloatware** | Запрет на повторную установку удаленных пакетов через реестр политики | `HKLM\SOFTWARE\Policies\Microsoft\Windows\CloudContent` → `DisableWindowsConsumerFeatures=1` | Windows может переустановить пакеты после первого подключения к интернету |

### БЛОК 8. СИСТЕМНАЯ КОНФИГУРАЦИЯ (Реестр HKLM + Групповые политики)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Применение глобальных настроек реестра, которые влияют на ВСЕХ пользователей |
| **Почему №8** | ПОСЛЕ удаления bloatware (Б07) и установки ПО (Б06), потому что некоторые ключи реестра зависят от наличия/отсутствия компонентов, а установщики ПО могли перезаписать настройки |
| **Критичность** | 🟢 **Средняя** |

**Подблоки Б08:**

| № | Подблок | Что делает | Целевые ветки реестра | Влияние |
|:---|:---|:---|:---|:---|
| 8.1 | **Отключение телеметрии (перманентное)** | Запрет сбора данных на уровне политик | `HKLM\SOFTWARE\Policies\Microsoft\Windows\DataCollection` → `AllowTelemetry=0` | Блокирует DiagTrack навсегда |
| 8.2 | **Отключение рекламных и потребительских функций** | Блокировка предложений в меню Пуск, Lock Screen, Tips | `HKLM\SOFTWARE\Policies\Microsoft\Windows\CloudContent`, `...\ContentDeliveryManager` | Чистый интерфейс без мусора для конечного пользователя |
| 8.3 | **Отключение AI-компонентов (Recall/Copilot/Widgets)** | Блокировка через Group Policy | `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsAI`, `...\WindowsCopilot`, `...\Dsh` | Экономия RAM, CPU, защита приватности |
| 8.4 | **Настройка Windows Update (политики)** | Установка режима «Только уведомление» или полного отключения | `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` | Предотвращает неконтролируемые обновления на клиенте |
| 8.5 | **Отключение автоматической установки драйверов** | Запрет Windows Update ставить драйверы без ведома пользователя | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\DriverSearching` → `SearchOrderConfig=0` | Защищает от замены стабильных драйверов на сломанные из WU |
| 8.6 | **Sysprep SkipRearm** | Сброс счетчика активации | `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform` → `SkipRearm=1` | Критично для многократного запуска Sysprep |

### БЛОК 10. ОПТИМИЗАЦИЯ И ГЛУБОКАЯ ОЧИСТКА СИСТЕМЫ

| Параметр | Значение |
|:---|:---|

| **Почему №10** | ПОСЛЕ всех установок и оптимизаций. Это ПОСЛЕДНИЙ блок, модифицирующий файловую систему перед Sysprep |
| **Критичность** |  **Высокая** |

### БЛОК 11. PRE-SYSPREP QA (Контроль качества перед запечатыванием)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Финальная проверка всех условий, необходимых для успешного прохождения Sysprep без ошибок |
| **Почему №11** | ПОСЛЕ всех модификаций, ПЕРЕД Sysprep. Это последняя возможность исправить проблемы |
| **Критичность** | 🔴 **Блокирующая** |

**Подблоки Б11:**

| № | Подблок | Что проверяет | Ожидаемый результат | Действие при сбое |
|:---|:---|:---|:---|:---|
| 11.1 | **Отсутствие pending reboots** | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\RebootPending` | Ключ отсутствует | Перезагрузка и повторная проверка |
| 11.2 | **Отсутствие pending пакетов DISM** | `DISM /Online /Get-Packages \| findstr Pending` | Пустой вывод | `DISM /Online /Cleanup-Image /RevertPendingActions` |
| 11.3 | **Проверка AppX-синхронизации** | Все пользователи имеют одинаковый набор AppX | `Get-AppxPackage -AllUsers` → нет пакетов только у одного пользователя | Удаление рассинхронизированных пакетов |
| 11.4 | **⚠️ Hot-Plug диск отключен** | В системе нет дополнительных дисков, кроме системного | `Get-Disk` → только Disk 0 | Отключить через меню VirtualBox → Устройства → Жесткие диски |

| 11.7 | **Свободное место на C:** | `Get-Volume C` | Минимум 10 ГБ свободно | Дополнительная очистка |
| 11.8 | **Сетевой адаптер отключен** | `Get-NetAdapter` | Нет адаптеров в статусе Up | Проверить настройки VirtualBox |

| Параметр | Значение |
