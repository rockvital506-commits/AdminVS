
## 1. Сущности образов и бэкапов

### Форматы дистрибуции/установки

| Формат | Уровень абстракции | Назначение | Преимущества | Ограничения |
|--------|-------------------|------------|--------------|-------------|
| **WIM** (Windows Imaging Format) | L5 (ФС + метаданные) | Стандартный образ для развертывания Windows. Содержит сжатую файловую систему с метаданными NTFS. | - Аппаратно-независимый<br>- Поддержка множественных образов в одном файле<br>- Сжатие без потерь<br>- Интеграция драйверов/обновлений | - Требует распаковки при установке<br>- Медленнее прямого копирования<br>- Не содержит загрузочных секторов |
| **ESD** (Electronic Software Download) | L5 (ФС + метаданные) | Сжатый WIM (LZMS/XPress) для цифровой дистрибуции Windows через Windows Update/Store. | - Высокая степень сжатия (на 30-40% меньше WIM)<br>- Шифрование (опционально)<br>- Быстрая передача по сети | - Медленная распаковка (CPU-intensive)<br>- Ограниченная поддержка сторонними утилитами<br>- Не все редакции DISM поддерживают |
| **ISO** (Optical Disc Image) | L3 (Блочный + ФС UDF/ISO9660) | Посекторный образ оптического диска. Контейнер для WIM/ESD + загрузочных файлов. | - Самодостаточный загрузочный носитель<br>- Универсальная совместимость<br>- Целостность структуры | - Фиксированный размер<br>- Нельзя модифицировать без пересоздания<br>- Избыточен для чистых образов системы |

### Форматы виртуализации/рабочего состояния

| Формат | Уровень абстракции | Назначение | Преимущества | Ограничения |
|--------|-------------------|------------|--------------|-------------|
| **VHD** (Virtual Hard Disk) | L2-L3 (Блочный + ФС) | Виртуальный диск Microsoft (Hyper-V, Virtual PC). Содержит разделы + ФС. | - Нативная загрузка (Windows 7+)<br>- Поддержка в Hyper-V/VirtualBox<br>- Монтирование как обычный диск | - Максимум 2040 GB<br>- Устаревший формат<br>- Нет checksum integrity |
| **VHDX** (Virtual Hard Disk v2) | L2-L3 (Блочный + ФС) | Улучшенная версия VHD (Windows 8+/Server 2012+). | - До 64 TB<br>- Журналирование (защита от сбоев)<br>- Trim/UNMAP поддержка<br>- Metadata (timestamp, custom props) | - Требует UEFI для Native Boot на новом железе<br>- Не поддерживается в старых ОС<br>- Больший оверхед метаданных |

### Проприетарные форматы бэкапов

| Формат | Утилита | Суть | Конвертация |
|--------|---------|------|-------------|
| **.pmf / .pmfx** | DiskGenius | Проприетарный блочный/файловый архив. Содержит посекторную копию или файловую структуру со сжатием. | Только через restore DiskGenius → затем capture в WIM |
| **.hbd / .DBI** | Hasleo Backup | Проприетарный контейнер инкрементальных/дифференциальных бэкапов. Поддерживает CBT, дедупликацию. | Только через Hasleo restore/mount → затем capture |

## 2. Алгоритм конвертации (Proprietary → Standard)

### ⚠️ АРХИТЕКТУРНОЕ ОГРАНИЧЕНИЕ

**Прямая конвертация `.pmf`/`.DBI` → `.wim/.iso` НЕВОЗМОЖНА** по следующим причинам:

1. **Структурные различия:**
   - `.pmf/.DBI` = проприетарный архив с собственной таблицей блоков, метаданными бэкапа, инкрементными цепочками
   - `.wim` = стандартизированный образ файловой системы с XML-метаданными, security descriptors, hardlinks

2. **Уровни абстракции:**
   - DiskGenius/Hasleo работают на L1-L3 (блоки, разделы)
   - WIM/ESD работают на L5 (ФС, реестр, драйверы)

### ✅ РЕШЕНИЕ: ДВУХЭТАПНАЯ КОНВЕРТАЦИЯ

```
Proprietary Backup (.pmf/.DBI)
         ↓
[Этап 1: Restore/Mount]
         ↓
VHD/VHDX или Live System
         ↓
[Этап 2: Capture]
         ↓
WIM/ESD → ISO
```

### ЭТАП 1: Восстановление или монтирование проприетарного бэкапа

#### Вариант А: DiskGenius (.pmf/.pmfx) → VHDX

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | DiskGenius → `Инструменты` → `Восстановление из образа` → выбрать `.pmf` | Инициализация распаковки проприетарного контейнера | 5 | Убедитесь, что на целевом диске достаточно места (≥ размер оригинала) |
| 2 | `Тип восстановления`: **Восстановить в виртуальный диск (VHD/VHDX)** | Создание совместимого контейнера вместо прямого восстановления на раздел | 5 | Не выбирайте "Восстановить на раздел" — это затрет данные |
| 3 | Путь: `P60:\Temp\DiskGenius_Temp.vhdx`<br>Тип: **Fixed VHDX** | Фиксированный размер исключает фрагментацию блоков при последующем capture | 4 | Fixed VHDX занимает всё место сразу. Убедитесь, что на P60 ≥60 GB свободно |
| 4 | `Начать` → дождаться завершения | Поблочная распаковка архива в структуру VHDX | 4 | Процесс занимает 15-45 минут в зависимости от размера .pmf |

#### Вариант Б: Hasleo (.hbd/.DBI) → Монтирование образа

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | Hasleo Backup → `Инструменты` → `Смонтировать образ` | Подключение проприетарного контейнера как виртуального диска без полной распаковки | 5 | Требует, чтобы цепочка инкрементов была полной (Full + все Inc) |
| 2 | Выбрать `.hbd` файл → `Смонтировать` | Hasleo создает временный VHDX в `%TEMP%` и монтирует его | 5 | Временный файл занимает место на системном диске. Убедитесь, что на C: ≥ размер образа |
| 3 | Запомнить букву диска (напр., `E:`) | Образ теперь доступен как обычный раздел для чтения | 5 | Не закрывайте Hasleo до завершения capture — образ размонтируется |
| 4 | **Альтернатива:** `Восстановить` → выбрать раздел `P60:\Temp\Hasleo_Temp\` | Полное восстановление файлов на временный раздел | 4 | Занимает больше времени, но надежнее для больших систем |

### ЭТАП 2: Захват (Capture) системы в формат WIM

#### Подготовка (общая для обоих вариантов)

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | Смонтировать VHDX: ПКМ на `P60:\Temp\*.vhdx` → `Подключить` | Windows назначает букву диска (напр., `F:`) для доступа к файлам | 5 | Если VHDX зашифрован BitLocker, сначала расшифруйте или введите ключ |
| 2 | Проверить структуру: `F:\Windows`, `F:\Program Files`, `F:\Users` | Убедитесь, что образ содержит полную систему, а не пустой раздел | 5 | Если папки отсутствуют — бэкап был поврежден или это не системный раздел |
| 3 | Запустить **CMD/PowerShell от имени Администратора** | DISM требует elevated privileges для захвата системных файлов | 5 | Запуск без прав админа приведет к ошибке `Access Denied` на файлах реестра |

#### Capture через DISM++ (GUI — рекомендуется для Beginner)

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | DISM++ → `Файл` → `Восстановить образ` → выбрать `F:\` | Загрузка оффлайн-образа Windows из смонтированного VHDX | 5 | DISM++ автоматически определит версию Windows и архитектуру |
| 2 | `Панель управления` → `Очистка` → `SFC/Component Store` | Удаление временных файлов, старых обновлений, кэша перед захватом | 4 | Очистка уменьшит размер WIM на 2-5 GB. Процесс занимает 10-20 минут |
| 3 | `Файл` → `Сохранить образ` → путь: `P60:\Images\Win11_Captured.wim`<br>Сжатие: **LZMS** (максимальное) | Создание WIM-образа с максимальным сжатием | 5 | LZMS медленнее, но экономит 30-40% места. Для быстрого захвата выберите `LZX` |
| 4 | Дождаться `Успешно` | DISM++ создает WIM с метаданными, security descriptors, hardlinks | 5 | Процесс занимает 20-60 минут в зависимости от объема данных и CPU |

#### Capture через DISM (CLI — для автоматизации)

```powershell
# Команда захвата образа
dism /Capture-Image `
  /ImageFile:"P60:\Images\Win11_Captured.wim" `
  /CaptureDir:"F:\" `
  /Name:"Windows 11 Pro Custom" `
  /Description:"Captured from DiskGenius/Hasleo backup" `
  /Compress:max `
  /CheckIntegrity `
  /Verify

# Параметры:
# /Compress:max — LZMS сжатие (альтернативы: none, fast, maximum)
# /CheckIntegrity — записать checksums для проверки целостности
# /Verify — верификация после захвата
```

| Параметр | Смысл | Эффективность | Риски |
|----------|-------|---------------|-------|
| `/Capture-Image` | Основная операция захвата ФС в WIM | 5 | Требует ≥10 GB свободного места на целевом диске |
| `/ImageFile` | Путь к создаваемому WIM | 5 | Если файл существует, DISM создаст новый образ ВНУТРИ существующего WIM (multi-image) |
| `/CaptureDir` | Корень захватываемой системы (буква смонтированного VHDX) | 5 | Не указывайте `C:\` если захватываете live-систему — получите inconsistent образ |
| `/Compress:max` | Максимальное сжатие (LZMS) | 4 | Медленнее, но экономит место. Для скорости используйте `/Compress:maximum` (LZX) |

### ЭТАП 3: Конвертация WIM → ESD (опционально)

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | PowerShell (Admin): `dism /Export-Image /SourceImageFile:"P60:\Images\Win11_Captured.wim" /SourceIndex:1 /DestinationImageFile:"P60:\Images\Win11_Compressed.esd" /Compress:recovery` | Конвертация WIM в ESD с максимальным сжатием Recovery (LZMS) | 4 | ESD на 30-40% меньше WIM, но создание занимает в 2-3 раза больше времени |
| 2 | Дождаться `Операция успешно завершена` | Создание ESD-контейнера | 4 | Процесс может занять 1-2 часа для образа 20-30 GB |

**Когда использовать ESD:**
- ✅ Для хранения архивов (экономия места на P60/SD400)
- ✅ Для передачи по сети (меньший трафик)
- ❌ Не используйте для частых модификаций (ESD нельзя редактировать без обратной конвертации в WIM)

## 3. Подготовка универсального образа (Sysprep)

### ⚠️ КРИТИЧЕСКИЕ ПРЕДУПРЕЖДЕНИЯ

1. **Sysprep необратим:** После `sysprep /generalize` система **теряет**:
   - Уникальный SID (Security Identifier)
   - Привязку к оборудованию (драйверы чипсета, NVMe, GPU)
   - Активацию Windows (требуется повторная)
   - Журналы событий, точки восстановления
   - Учетные данные пользователей (кроме встроенного Administrator)

2. **Лимит запусков:** Windows позволяет запускать `sysprep /generalize` **максимум 3 раза** на одной установке. Превышение приведет к ошибке `Sysprep has been run too many times`.

3. **Точка невозврата:** После sysprep **невозможно** откатить систему к предыдущему состоянию. Всегда создавайте бэкап **перед** sysprep!

---

### АЛГОРИТМ: Sysprep перед захватом образа

#### Вариант А: Sysprep на live-системе (перед созданием бэкапа)

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | Установите Windows, драйверы, софт | Подготовка эталонной системы | 5 | Не устанавливайте специфичные драйверы (GPU, принтеры) — они будут удалены при generalize |
| 2 | Удалите пользовательские данные, очистите корзину | Sysprep не удаляет файлы пользователей автоматически | 5 | Если не очистить, данные попадут в универсальный образ (безопасность!) |
| 3 | CMD (Admin): `C:\Windows\System32\Sysprep\sysprep.exe` | Запуск утилиты системной подготовки | 5 | Запуск от имени администратора обязателен |
| 4 | Параметры:<br>✔ **Переход в окно приветствия (OOBE)**<br>✔ **Подготовка к использованию (Generalize)**<br>✔ **Завершение работы (Shutdown)** | Generalize удаляет SID, драйверы, привязку к железу. OOBE запускает первоначальную настройку при следующей загрузке. | 5 | **НЕ выбирайте "Перезагрузка"** — система загрузится в обобщенном состоянии, что создаст новые SID и сломает образ |
| 5 | Дождитесь завершения (5-15 минут) и выключения ПК | Sysprep очищает систему и выключает питание | 5 | Не прерывайте процесс! Прерывание = неработоспособная система |
| 6 | **Сразу после выключения:** загрузитесь с WinPE (Strelec/Hasleo PE) | Захват образа из выключенного состояния | 5 | Не включайте систему после sysprep! Загружайтесь только в WinPE |
| 7 | Смонтируйте диск C: в WinPE → выполните **Capture** через DISM++ | Создание WIM из обобщенной системы | 5 | Образ будет универсальным — загрузится на любом железе с UEFI |

#### Вариант Б: Sysprep из смонтированного образа (offline)

Если у вас уже есть бэкап (DiskGenius/Hasleo) и вы не хотите запускать live-систему:

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | Восстановите бэкап на виртуальный диск (VHDX) | Подготовка к offline-модификации | 5 | Требуется ≥60 GB свободного места на P60 |
| 2 | Смонтируйте VHDX → запомните букву (напр., `F:`) | Доступ к файлам системы | 5 | Убедитесь, что VHDX не зашифрован BitLocker |
| 3 | PowerShell (Admin):<br>`dism /Image:F:\ /Cleanup-Image /StartComponentCleanup` | Очистка Component Store перед sysprep | 4 | Уменьшает размер образа на 2-4 GB |
| 4 | PowerShell (Admin):<br>`dism /Image:F:\ /Enable-Feature /FeatureName:Microsoft-Windows-Sysprep` | Убедитесь, что Sysprep включен (по умолчанию включен) | 3 | Обычно не требуется, но полезно проверить |
| 5 | **Offline Sysprep НЕ поддерживается напрямую!**<br>Альтернатива: загрузитесь с VHDX (Native Boot) → выполните **Вариант А** | Sysprep требует загрузки ОС для корректной работы | 2 | Offline-сценарии через `dism` не выполняют полный generalize |

**Рекомендация:** Всегда используйте **Вариант А** (live-система → sysprep → shutdown → capture из WinPE). Это единственный надежный способ создать универсальный образ.

### КОМАНДНАЯ СТРОКА SYSPREP (для скриптов)

```cmd
:: Полный generalize с OOBE и shutdown
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown /mode:vm

:: Параметры:
:: /generalize — удалить SID, драйверы, привязку к железу
:: /oobe — запуск окна приветствия при следующей загрузке
:: /shutdown — выключение после завершения
:: /mode:vm — оптимизация для виртуальных машин (опционально)
```

| Параметр | Когда использовать |
|----------|-------------------|
| `/generalize` | **Всегда** для универсальных образов. Без этого параметра образ загрузится только на исходном железе. |
| `/oobe` | Для образов, которые будут разворачиваться конечным пользователям (настройка региона, учетной записи). |
| `/audit` | Для образов, которые будут дорабатываться (установка софта, обновлений) перед финальным generalize. |
| `/shutdown` | **Всегда** перед захватом образа. Никогда не используйте `/reboot`! |

## 4. Развертывание и установка (Таблицы)

### Сценарий 1: Развертывание WIM/ESD на физический диск (UEFI/GPT)

| Шаг | Действие (CLI/GUI) | Смысл (First Principles) | Эффективность (1-5) | Риски |
|-----|-------------------|-------------------------|---------------------|-------|
| 1 | Загрузиться с WinPE (Strelec/Hasleo PE) с USB (SD400) | WinPE предоставляет минимальную ОС с DISM, DiskPart, сетевыми драйверами | 5 | Убедитесь, что WinPE загружен в **UEFI режиме** (не Legacy), иначе не создастся EFI раздел |
| 2 | DiskPart:<br>`diskpart`<br>`list disk`<br>`select disk 0` (целевой диск)<br>`clean`<br>`convert gpt` | Полная очистка диска и конвертация в GPT для UEFI загрузки | 5 | **ВНИМАНИЕ:** `clean` удаляет ВСЕ данные на диске! Убедитесь, что выбран правильный диск |
| 3 | DiskPart создание разделов:<br>`create partition efi size=100`<br>`format quick fs=fat32 label="System"`<br>`assign letter=S`<br>`create partition primary`<br>`format quick fs=ntfs label="Windows"`<br>`assign letter=W` | Создание EFI раздела (100 MB, FAT32) и основного раздела Windows (NTFS) | 5 | EFI раздел **обязательно** должен быть FAT32. NTFS не загрузится в UEFI |
| 4 | DISM Apply-Image:<br>`dism /Apply-Image /ImageFile:"P60:\Images\Win11_Universal.wim" /Index:1 /ApplyDir:W:\` | Распаковка WIM-образа на целевой раздел | 5 | Процесс занимает 10-30 минут. Не прерывайте питание! |
| 5 | Создание BCD:<br>`bcdboot W:\Windows /s S: /f UEFI` | Копирование загрузочных файлов (`bootmgfw.efi`) на EFI раздел и создание BCD-хранилища | 5 | Без этого шага система **не загрузится** с ошибкой `No bootable device` |
| 6 | `exit` → перезагрузка → извлечь WinPE USB | Завершение работы WinPE | 5 | Не забудьте извлечь USB, иначе ПК загрузится с него снова |
| 7 | Первая загрузка → OOBE (настройка региона, учетной записи) | Windows запускает первоначальную настройку | 5 | Если образ не был generalized, пропустите OOBE и загрузитесь в существующую систему |

### Сценарий 2: Развертывание на VHD/VHDX (Native Boot или VM)

| Шаг | Действие (CLI/GUI) | Смысл (First Principles) | Эффективность (1-5) | Риски |
|-----|-------------------|-------------------------|---------------------|-------|
| 1 | PowerShell (Admin):<br>`New-VHD -Path "P60:\WTG\Win11_Universal.vhdx" -SizeBytes 64GB -Dynamic` | Создание динамического VHDX (растет по мере заполнения) | 5 | Dynamic VHDX медленнее Fixed, но экономит место. Для WTG используйте **Fixed**: `-Dynamic:$false` |
| 2 | PowerShell:<br>`Mount-VHD -Path "P60:\WTG\Win11_Universal.vhdx"`<br>`Get-Disk \| Where-Object {$_.IsOffline -eq $true} \| Initialize-Disk -PartitionStyle GPT` | Монтирование VHDX как виртуального диска и инициализация GPT | 5 | VHDX появится как новый диск в Disk Management. Запомните номер диска |
| 3 | DiskPart или PowerShell создание разделов:<br>`New-Partition -DiskNumber 1 -Size 100MB -FileSystem FAT32 -AssignDriveLetter S`<br>`New-Partition -DiskNumber 1 -UseMaximumSize -FileSystem NTFS -AssignDriveLetter W` | Создание EFI (S:) и Windows (W:) разделов внутри VHDX | 5 | Для **Native Boot** VHDX должен содержать EFI раздел. Для VM (Hyper-V) достаточно одного NTFS раздела |
| 4 | DISM Apply-Image:<br>`dism /Apply-Image /ImageFile:"P60:\Images\Win11_Universal.wim" /Index:1 /ApplyDir:W:\` | Распаковка образа на VHDX | 5 | Аналогично физическому диску. Занимает 10-30 минут |
| 5 | Создание BCD:<br>`bcdboot W:\Windows /s S: /f UEFI` | Загрузка VHDX будет работать только с правильным BCD | 5 | Для **Native Boot** BCD должен быть на хостовой системе (см. шаг 6) |
| 6 | **Native Boot:** Добавить VHDX в меню загрузки:<br>`bcdedit /copy {current} /d "Windows 11 VHDX"`<br>`bcdedit /set {GUID} device vhd=[P60:]\WTG\Win11_Universal.vhdx`<br>`bcdedit /set {GUID} osdevice vhd=[P60:]\WTG\Win11_Universal.vhdx`<br>`bcdedit /set {GUID} path \windows\system32\boot\winload.efi` | Регистрация VHDX в BCD хостовой Windows для загрузки при старте ПК | 4 | **GUID** — это идентификатор из шага `bcdedit /copy`. Замените `{GUID}` на реальный ID. Ошибка в пути = `Inaccessible Boot Device` |
| 7 | **VirtualBox:** Создать ВМ → `Existing Hard Disk` → выбрать VHDX | Использование VHDX как виртуального диска в VirtualBox | 5 | VirtualBox требует VHDX в формате **VDI** или **VMDK**. Конвертируйте: `VBoxManage clonehd "file.vhdx" "file.vdi" --format VDI` |
| 8 | **VMware:** Создать ВМ → `Use an existing virtual disk` → выбрать VHDX | VMware Workstation нативно поддерживает VHDX | 5 | VMware может потребовать конвертацию в VMDK для полной совместимости |

### Сценарий 3: Развертывание из проприетарных бэкапов (.pmf/.DBI) напрямую

Если вам не нужен универсальный образ, а просто восстановить систему на том же или похожем железе:

| Шаг | Действие | Смысл | Эффективность | Риски |
|-----|----------|-------|---------------|-------|
| 1 | **DiskGenius:** Загрузиться с WinPE → `Инструменты` → `Восстановление из образа` → выбрать `.pmf` | Прямое восстановление проприетарного бэкапа | 5 | DiskGenius восстановит **точную копию** включая SID, драйверы, привязку к железу |
| 2 | Целевой раздел: выбрать диск C: (или новый SSD) | Восстановление на целевой носитель | 5 | **ВНИМАНИЕ:** Все данные на целевом разделе будут уничтожены |
| 3 | `Восстановить загрузочные записи` (галочка) | DiskGenius автоматически восстановит MBR/GPT и BCD | 4 | Если не отметить, система не загрузится. Придется чинить BCD вручную |
| 4 | `Начать` → дождаться завершения | Поблочная запись данных | 4 | Занимает 20-60 минут в зависимости от объема |
| 5 | **Hasleo:** Аналогично → `Восстановить` → выбрать `.hbd` → целевой диск | Hasleo восстановит полную цепочку (Full + Inc) | 5 | Hasleo автоматически соберет инкременты в единый образ перед записью |
| 6 | Первая загрузка | Проверка работоспособности | 5 | Если восстанавливаете на **другое железо**, возможен BSOD `INACCESSIBLE_BOOT_DEVICE` из-за отсутствия драйверов контроллера диска |

**Критическое отличие от универсального образа:**
- Прямое восстановление (.pmf/.DBI → диск) = **клонирование** (сохраняет SID, драйверы, привязку к железу)
- WIM/VHDX с sysprep = **универсальный образ** (загрузится на любом железе)

## 5. Итоговая рекомендация по выбору формата

### Матрица выбора

| Ваша цель | Формат | Утилита | Почему |
|-----------|--------|---------|--------|
| **Быстрое восстановление на том же ПК** | `.pmf` / `.DBI` | DiskGenius / Hasleo | Не требует конвертации. Восстановление за 1 клик. Сохраняет все настройки, драйверы, активацию. |
| **Универсальный образ для развертывания на разные ПК** | **WIM** → ISO | DISM++ / OSCDIMG | Аппаратно-независимый. Стандарт индустрии. Легко интегрировать драйверы/обновления. |
| **Windows To Go (загрузка с внешнего SSD)** | **Fixed VHDX** | Hasleo Backup / DiskGenius | Нативная загрузка с USB. Переносимость между ПК. Сохранение изменений (persistent). |
| **Архивное хранение (экономия места)** | **ESD** | DISM / NTLite | На 30-40% меньше WIM. Идеально для SD400 (exFAT 512K). |
| **Виртуальные машины (VirtualBox/VMware)** | **Dynamic VHDX** → VDI/VMDK | PowerShell / VBoxManage | Dynamic экономит место. Конвертация в VDI/VMDK обеспечивает совместимость. |
| **Ежедневные бэкапы с инкрементами** | **.DBI** (Hasleo) | Hasleo Backup | CBT отслеживает изменения. Быстро, экономит место. Не требует sysprep. |

### Оптимальный workflow для вашей сборки

```
1. Еженедельный бэкап:
   Hasleo Backup → Full (воскресенье) + Incremental (понедельник-суббота)
   Хранение: P60:\Hasleo\Backups\
   Формат: .DBI (проприетарный, быстрый restore)

2. Ежемесячный универсальный образ:
   Live System → Sysprep /generalize → Shutdown
   WinPE → DISM++ Capture → WIM
   Конвертация: WIM → ESD (для экономии)
   Хранение: P60:\Images\Win11_Universal_2026-06.wim

3. Windows To Go:
   Hasleo → System Clone → Export to VHDX (Fixed, 64GB)
   Размещение: P60:\WTG\Win11_WTG.vhdx
   Загрузка: Ventoy + ventoy_vhdboot.img

4. Аварийное восстановление:
   DiskGenius .pmf бэкап (полный клон диска)
   Хранение: SD400:\Emergency\Disk_Clon.pmf
   Использование: Только при критическом сбое
```

### Золотое правило

**Никогда не полагайтесь на один формат!**

- ✅ **Hasleo .DBI** — для быстрых ежедневных откатов
- ✅ **WIM/VHDX** — для универсального развертывания и WTG
- ✅ **DiskGenius .pmf** — для аварийного клона на случай смерти диска

Храните все три типа бэкапов на разных носителях (P60 + SD400). Это обеспечит максимальную надежность и гибкость восстановления.
