## Анализ применимости сетевого подключения в условиях изоляции
Для однозначности выводов проведена техническая экспертиза: как подключить сетевую папку (SMB), если в Блоке 5.1 мы выключили сетевой адаптер, чтобы Windows Store не сломал Sysprep обновлением AppX-пакетов?

* Прямое противоречие: Без сетевого адаптера протокол SMB (сетевая папка) физически не работает.
* Инженерное решение: Использование изолированного сетевого адаптера типа «Виртуальный адаптер хоста» (Host-Only Adapter).
* Почему это безопасно для Sysprep: Этот тип сети создает изолированный кабель строго между хостом и ВМ. В нем полностью отсутствует доступ к интернету и шлюзам провайдера. Windows Store физически не сможет связаться с серверами Microsoft, при этом локальный обмен файлами по протоколу SMB (TCP 445) между физическим ПК и ВМ будет работать на максимальной скорости.

## БЛОК 1. Конфигурация изолированного сетевого периметра в VirtualBox 7.2.10## 1.1. Создание Host-Only сети в гипервизоре

   1. В главном окне VirtualBox 7.2.10 нажмите меню Инструменты (Tools) -> выберите Сеть (Network) -> вкладка Виртуальные сети хоста (Host-Only Networks).
   2. Нажмите кнопку Создать (Create). Появится адаптер с именем (например, VirtualBox Host-Only Ethernet Adapter).
   3. Вкладка Адаптер (Adapter) -> Настроить вручную (Configure Adapter Manually):
   * IPv4 адрес: 192.168.56.1
      * IPv4 маска подсети: 255.255.255.0
   4. Вкладка DHCP-сервер (DHCP Server) -> Строго Снять галочку «Включить сервер».
   * Обоснование: Статическое назначение IP-адресов внутри эталонной ВМ исключает задержки инициализации сети при загрузке.
   
## 1.2. Привязка адаптера к эталонной ВМ

   1. Выключите ВМ. Откройте Настройки ВМ -> Сеть -> вкладка Адаптер 1.
   2. Поставьте галочку «Включить сетевой адаптер».
   3. В поле «Тип подключения» (Attached to) выберите: Виртуальный адаптер хоста (Host-Only Adapter).
   4. В поле «Имя» (Name) выберите созданный ранее: VirtualBox Host-Only Ethernet Adapter.
   5. Разверните вкладку «Дополнительно» -> «Кабель подключен»: Да (Галочка поставлена).

## БЛОК 2. Подготовка и развертывание SMB-ресурса на Хост-ПК## 2.1. Создание каталога и авторизация

   1. На физическом хост-ПК (Windows) создайте папку на диске, например: C:\VM_Exchange.
   2. Кликните правой кнопкой мыши по папке -> Свойства -> вкладка Доступ -> кнопка Расширенная настройка.
   3. Поставьте галочку «Открыть общий доступ к этой папке». Нажмите кнопку Разрешения.
   4. Убедитесь, что в списке есть группа «Все», и выставьте ей галочки: Полный доступ, Изменение, Чтение. Нажмите Применить -> ОК.
   5. Перейдите во вкладку Безопасность (права NTFS) -> кнопка Изменить -> Добавить -> введите Все -> ОК. Выставьте группе «Все» права Полный доступ.

## 2.2. Проверка сетевого профиля Хоста

   1. На Хосте откройте Панель управления -> Центр управления сетями и общим доступом -> Изменить дополнительные параметры общего доступа.
   2. Для профиля Частная и Гостевая или общедоступная выберите: Включить сетевое обнаружение и Включить общий доступ к файлам и принтерам.
   3. В разделе Все сети:
   * Включить общий доступ, чтобы пользователи сети могли читать и записывать файлы.
      * Отключить общий доступ с парольной защитой (для этапа сборки образа это снизит вероятность блокировки протокола NTLMv2 из ВМ).

## БЛОК 3. Настройка гостевой ОС Windows 10/11 в ВМ## 3.1. Статическая разметка IP-адресов

   1. Запустите ВМ. Нажмите Win + R -> введите ncpa.cpl.
   2. Кликните правой кнопкой мыши по сетевому адаптеру -> Свойства -> выберите IP версии 4 (TCP/IPv4) -> Свойства.
   3. Выберите «Использовать следующий IP-адрес»:
   * IP-адрес: 192.168.56.10
      * Маска подсети: 255.255.255.0
      * Основной шлюз: Оставить ПУСТЫМ
      * Предпочитаемый DNS-сервер: Оставить ПУСТЫМ
      * Критический комментарий: Отсутствие шлюза и DNS аппаратно гарантирует, что ВМ не сможет совершить маршрутизацию пакетов за пределы хоста.
   
## 3.2. Перевод сети в доверенный статус
По умолчанию неопознанная сеть без шлюза блокируется встроенным брандмауэром Windows.

   1. Откройте PowerShell от имени Администратора внутри ВМ и выполните:
   
   Get-NetConnectionProfile | Set-NetConnectionProfile -NetworkCategory Private
   
   * Результат: Сетевой профиль Host-Only соединения перейдет в статус «Частная», что автоматически откроет порты для SMB-клиента.

## БЛОК 4. Подключение и маппинг сетевой папки внутри ВМ
Для обеспечения надежного соединения, которое не отвалится при чистке профилей, подключайте папку как сетевой диск через командную строку.

   1. Внутри ВМ откройте командную строку от админа и введите команду:
   
   net use Z: \\192.168.56.1\VM_Exchange /persistent:no
   
   * Флаг /persistent:no указывает системе не восстанавливать этот диск при следующей загрузке. Это критично: при первом запуске целевого ПК после Sysprep система не должна пытаться искать несуществующий хост 192.168.56.1, что предотвратит зависание службы проводника (explorer.exe).
   2. В Проводнике ВМ появится диск Z:. Перенесите туда необходимые утилиты дефрагментации, чистки или скрипты.
   3. Перед запуском Sysprep: Выполните команду размонтирования:
   
   net use Z: /delete

## БЛОК 5. Матрица траблшутинга (Ошибки и исправления)
Если при вводе команды net use возникает сбой, определите код ошибки и примените строгое решение:
## Ошибка 1: «Сетевой путь не найден» (Системная ошибка 53)

* Причина: Физический брандмауэр Хоста блокирует входящие пакеты на порт TCP 445 от интерфейса VirtualBox.
* Решение (на Хост-ПК): Откройте PowerShell от админа и выполните команду, открывающую доступ для подсети ВМ:

New-NetFirewallRule -DisplayName "VBox_SMB" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 445 -RemoteAddress 192.168.56.0/24


## Ошибка 2: «Вход в систему не выполнен: ограничение учетной записи» (Системная ошибка 1326 / 0x8007052e)

* Причина: Локальная политика безопасности Хоста блокирует гостевой вход без пароля для учетных записей с пустыми паролями.
* Решение 1: Принудительно передайте имя локального пользователя хоста (например, AdminHost) и его пароль (Pass123) при подключении диска в ВМ:

net use Z: \\192.168.56.1\VM_Exchange /user:AdminHost Pass123 /persistent:no

* Решение 2 (Если на хосте нет пароля): На Хост-ПК откройте secpol.msc -> Локальные политики -> Параметры безопасности -> Найдите: Учетные записи: ограничить использование пустых паролей только консольным входом -> Переведите в статус Отключено.

## Ошибка 3: «Вы не можете получить доступ к этой общей папке, так как политики безопасности блокируют гостевой доступ без проверки подлинности» (Windows 10/11)

* Причина: Безопасность современных Windows блокирует незащищенный протокол SMB2/SMB3 Guest Access.
* Решение (Внутри ВМ): Откройте PowerShell от админа в ВМ и принудительно разрешите небезопасный гостевой вход в реестре:

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters" -Name "AllowInsecureGuestAuth" -Value 1

## Критический анализ и верификация мануала:
Предложенный пошаговый цикл изолирует ВМ от внешнего интернета, решает проблему блокировки портов брандмауэром без шлюза (через смену категории сети на Private) и устраняет ошибки авторизации Windows 10/11. Флаг /persistent:no гарантирует, что структура сетевых подключений останется девственно чистой на этапе работы Sysprep.
