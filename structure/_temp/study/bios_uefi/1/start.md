# **ШАГ 0: Подготовка изолированной среды**
- *Как*: WSL2/WSA + Ventoy USB (V:exFAT для ISO, W:NTFS для данных) + WinPE образ.
- *Для чего*: Отделить эксперименты от основной Win11.
- *Почему*: Ошибки в BCD/ESP/NVRAM могут привести к незагрузке хост-системы.

# **ШАГ 1: GPT и ESP (структура и маунт)**
- *Как*: `diskpart` → `list disk` → `select disk X` → `list part` → `assign letter=Z` для ESP. `hexedit`/`UEFI-Parser` для анализа LBA0-32.
- *Для чего*: Понять, где лежит загрузчик и как GPT защищает разделы.
- *Почему*: Без корректной ESP UEFI не найдет `.efi`. Protective MBR предотвращает случайную запись legacy-тулзами.

# **ШАГ 2: UEFI фазы (фокус на DXE)**
- *Как*: Изучить `UEFITool` → открыть образ BIOS → перейти к `DXE Driver` разделу. Чтение спецификации `PI (Platform Initialization) 1.6`.
- *Для чего*: Понять, как инициализируются контроллеры, шины и протоколы до передачи управления OS.
- *Почему*: DXE определяет совместимость устройств и скорость POST. Ошибки здесь → freeze на логотипе вендора.

# **ШАГ 3: NVRAM и UEFI-переменные**
- *Как*: `efibootmgr -v` (Linux) / `Get-WindowsDriver` + реестр `HKLM\SYSTEM\CurrentControlSet\Control` (Windows mirror). Чтение `UEFI Spec §8.2`.
- *Для чего*: Узнать, где хранятся BootOrder, SecureBoot keys, таймауты.
- *Почему*: Прямая запись через неподписанные утилиты → corruption → сброс настроек или отказ загрузки. Всегда делайте экспорт `vars.bin` перед изменениями.

# **ШАГ 4: Цепочка загрузки Windows 11**
- *Как*: `bcdedit /enum firmware` → отследить путь `\EFI\Microsoft\Boot\bootmgfw.efi` → `winload.efi` → `ntoskrnl.exe`. Включить `bootlog` в `msconfig`.
- *Для чего*: Визуализировать переход от firmware к ядру ОС.
- *Почему*: 70% проблем с "черным экраном" решаются анализом BCD и целостностью `bootmgfw.efi`/`winload.efi`.

# **ШАГ 5: Инструментарий и работа с образами**
- *Как*: `wimlib-imagex mount` для `.wim`, `dism /get-imageinfo` для `.esd`. Ventoy: автоматический маппинг ISO→EFI bootmenu.
- *Для чего*: Научиться извлекать/заменять драйверы и загрузчики без распаковки на диск.
- *Почему*: Прямое редактирование `.iso` ломает подпись/структуру. Монтирование + `imagex` сохраняет целостность.

# **ШАГ 6: Безопасность и вендорная совместимость**
- *Как*: Проверить SecureBoot state в UEFI Setup. Изучить vendor manuals (ASUS/HP/Dell/Lenovo) для recovery-режимов. Тест `chipsec` (только чтение).
- *Для чего*: Понять ограничения кастомных загрузчиков и пути восстановления после сбоя.
- *Почему*: SecureBoot блокирует неподписанные `.efi`. Venдоры используют разные Capsule-форматы и recovery-триггеры.

# **ШАГ 7: Практический лаб (без записи в SPI)**
- *Как*: Создать кастомный `grubx64.efi`/`bootx64.efi` на Ventoy. Протестировать загрузку WinPE → диагностика BCD → восстановление через `bootrec /fixboot /rebuildbcd`.
- *Для чего*: Закрепить цепочку в безопасной песочнице.
- *Почему*: Реальный ремонт начинается с умения восстановить ESP/BCD без перепрошивки BIOS.

# [IF SOFT] 🎓 Ментор (пояснения для beginner)
- `UEFITool` vs `RWEverything`: UEFI-Tool парсит структуру прошивки (безопасно, чтение). RWEveryhing дает прямой доступ к PCIe/SPI (риск зависания, только в WinPE).
- `NVRAM` ≠ CMOS: NVRAM хранит переменные в SPI, CMOS только RTC/базовые настройки. Сброс NVRAM ≠ снятие батарейки.
- `Ventoy` алгоритм: Мапит ISO в виртуальный CD-ROM через UEFI `blockio` → передает управление `bootx64.efi` внутри образа. Не требует распаковки.
- `DXE` trap: Если драйвер NVMe/USB не загружен в DXE → ESP не примонтируется → Windows не стартует. Проверяйте `UEFI USB Support` и `CSM` (должен быть `Disabled`).
- Масштабирование: После освоения шагов 1-4 переходите к `edk2` (сборка кастомных UEFI-модулей) и `chipsec` (аудит SecureBoot/TPM).
