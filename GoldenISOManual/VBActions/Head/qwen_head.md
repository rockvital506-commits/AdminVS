# 📋 ИТОГОВЫЙ МАНУАЛ: Подготовка Golden Image Windows 10/11 в VirtualBox 7.2.10

##  КРИТИЧЕСКИЕ ИЗМЕНЕНИЯ ПОСЛЕ АНАЛИЗА

1. **Блок 02 упрощен**: Удалено создание фиктивного пользователя "Admin". Вход в Audit Mode через `Ctrl+Shift+F3` на экране OOBE.
2. **Порядок Bloatware**: Блок удаления AppX перемещен ПОСЛЕ установки ПО (инсталляторы восстанавливают UWP-зависимости).
3. **Двухфазная блокировка**: Добавлен блок Б03B для повторной блокировки служб после установки ПО.
4. **Hot-Plug VDI**: Заменяет Shared Folder (не требует Guest Additions, не загрязняет PnP-дерево).
5. **Pre-Sysprep QA**: Расширен проверкой Hot-Plug диска и Guest Additions.

## БЛОК 00. PRE-FLIGHT: Подготовка на хосте (до запуска ВМ)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Подготовка всех offline-артефактов и Hot-Plug диска на хост-машине до первого запуска ВМ |
| **Почему №0** | ВМ изолирована от интернета. Все пакеты, драйверы, скрипты и утилиты должны быть физически доступны через Hot-Plug диск до начала работы |
| **Критичность** | 🔴 **Блокирующая** — без этого блока все последующие блоки невозможны |
| **Где выполняется** | Хост-ОС (Win11 Vivobook), не внутри ВМ |

### Подблоки Б00:

| № | Подблок | Что делает | Что подготавливается | Риск при пропуске | Критичность |
|:---|:---|:---|:---|:---|:---|
| 0.1 | **Скачивание offline-обновлений (MSU/CAB)** | Загрузка SSU, LCU, .NET Framework | Файлы `.msu`, `.cab` в папке `HotPlug:\Updates\` | Sysprep на устаревшей сборке может иметь известные баги |  |
| 0.2 | **Скачивание пакетов драйверов** | Загрузка универсальных драйверов (NVMe, USB 3.x, Intel RST/VMD, LAN/WLAN) | Папки с `.inf` в `HotPlug:\Drivers\` | Целевой ПК не загрузится после деплоя без критичных драйверов хранилища | 🔴 |
| 0.3 | **Подготовка скриптов автоматизации** | Копирование PowerShell/CMD скриптов (complete_cleaner.ps1, clean_hkcu.ps1 и др.) | `HotPlug:\Scripts\` | Ручное выполнение = человеческий фактор = нестабильный образ | 🟡 |
| 0.4 | **Подготовка портативного ПО** | Копирование установщиков (silent/unattended) и портативных утилит | `HotPlug:\Software\` | Невозможность установить нужный софт в изолированной среде |  |
| 0.5 | **Создание Hot-Plug VDI диска** | Создание виртуального диска 20-40 ГБ, форматирование NTFS, включение флага Hot-Pluggable | `HotPlug.vdi`, примонтирован как SATA порт 1 | Нет механизма передачи файлов в изолированную ВМ | 🔴 |

| **Почему №1** | Все дальнейшие манипуляции происходят внутри этой ВМ. Ошибки на этом этапе (например, Shared Folder) приведут к загрязнению PnP-дерева |
| **Критичность** | 🔴 **Блокирующая** |

## БЛОК 02. Установка Windows и вход в Audit Mode

| Параметр | Значение |
|:---|:---|
| **Назначение** | Развертывание чистой базовой ОС и немедленный переход в сервисный режим (Audit Mode) для работы под встроенным Администратором |
| **Почему №2** | Audit Mode — единственно верная среда для сборки Golden Image. Она изолирована от OOBE и не создает лишних пользовательских профилей |
| **Критичность** | 🔴 **Блокирующая** |

### Подблоки Б02:

| № | Подблок | Что делает | Метод / Команда | Почему именно здесь | Критичность |
|:---|:---|:---|:---|:---|:---|
| 2.1 | **Установка базовой ОС** | Стандартная установка Windows 10/11 Pro | Загрузка с ISO, выбор редакции **Pro** | Редакция Pro обязательна для поддержки gpedit и полноценного Sysprep. | 🔴 |
| 2.2 | **Перехват OOBE и вход в Audit Mode** | Пропуск создания пользователя и переход в сервисный режим | На первом экране OOBE (выбор региона) нажать **`Ctrl + Shift + F3`** | Система перезагрузится и автоматически войдет под встроенным `Administrator`. | 🔴 |
| 2.3 | **Верификация Audit Mode** | Проверка, что мы в правильном режиме | На рабочем столе должно быть открыто окно **Sysprep Tool**. В CMD: `whoami` должен вернуть `nt authority\system` или `administrator`. | Гарантия, что мы не в обычном режиме OOBE. | 🔴 |
| 2.4 | **Снимок ВМ (Критично)** | Создание точки отката | VirtualBox Manager -> Snapshots -> Take Snapshot ("Clean Audit Mode") | Если вы сломаете систему на этапе блокировки служб, вы откатитесь сюда за 5 секунд. | 🔴 |

## БЛОК 03A. ПЕРВИЧНАЯ БЛОКИРОВКА ФОНОВОЙ АКТИВНОСТИ

| Параметр | Значение |
|:---|:---|
| **Назначение** | Мгновенное подавление всех служб и процессов, которые могут модифицировать систему в фоне |
| **Почему №3A** | Должен выполняться СРАЗУ после входа в Audit Mode. Если Windows Update или Store успеет обновить AppX-пакет — Sysprep упадет |
| **Критичность** | 🔴 **Блокирующая для Sysprep** |

### Подблоки Б03A:

| № | Подблок | Что блокируется / останавливается | Метод | Риск при пропуске | Критичность |
|:---|:---|:---|:---|:---|:---|
| 3A.1 | **Службы Windows Update** | `wuauserv`, `UsoSvc`, `WaaSMedicSvc`, `dosvc`, `BITS` | `sc config` + `Set-Service` → Disabled | Фон. загрузка обновлений → изменение состояния AppX → Sysprep crash. | 🔴 |
| 3A.2 | **Microsoft Store / CloudContent** | `InstallService`, `AppXSvc`, `ClipSVC` | `Set-Service` → Disabled | Store может самообновить provisioned packages. | 🔴 |
| 3A.3 | **Диагностическая телеметрия** | `DiagTrack`, `dmwappushservice`, `WerSvc` | `Set-Service` → Disabled | Фоновая активность, запись логов, потребление I/O. | 🟡 |
| 3A.4 | **Критичные задачи планировщика** | `\Microsoft\Windows\WindowsUpdate\*`, `\Setup\*` | `schtasks /Change /Disable` | Фоновые триггеры могут запустить обновление в неподходящий момент. | 🔴 |

## БЛОК 04. OFFLINE-ОБНОВЛЕНИЕ СИСТЕМЫ (DISM Servicing)

| Параметр | Значение |
|:---|:---|
| **Назначение** | Установка всех кумулятивных обновлений, SSU, .NET Framework в образ без интернета |

| **Критичность** | 🟡 **Высокая** |

### Подблоки Б04:

| № | Подблок | Что делает | Механизм | Зависимости | Критичность |

| 5.2 | **Интеграция сетевых драйверов** | Гарантия наличия сети после деплоя | Intel I219/I225/I226, Realtek RTL8125/8111, Intel Wi-Fi 6/6E/7 | Б00.2 | 🟡 |

## БЛОК 03B. ПОВТОРНАЯ БЛОКИРОВКА И УДАЛЕНИЕ ВОССТАНОВЛЕННЫХ UWP

| Параметр | Значение |
|:---|:---|

## БЛОК 07. УДАЛЕНИЕ BLOATWARE И APPX-ПАКЕТОВ

| Параметр | Значение |
|:---|:---|
| **Назначение** | Полное удаление всех предустановленных UWP/AppX приложений + Win32 мусора |
| **Почему №7** | ПОСЛЕ установки ПО (Б06) и повторной блокировки (Б03B). Sysprep требует, чтобы у ВСЕХ пользователей не было AppX-пакетов, которых нет у других |
| **Критичность** | 🔴 **Блокирующая для Sysprep** |

### Подблоки Б07:

| № | Подблок | Что делает | Полный список удаляемых сущностей | Риск при пропуске | Критичность |
|:---|:---|:---|:---|:---|:---|
| 7.1 | **Удаление Provisioned AppX** | Удаляет пакеты из образа так, что они не появятся при создании новых профилей | Xbox*, Bing*, Zune*, People, Skype, OfficeHub, Solitaire, FeedbackHub, MixedReality, Widgets, Copilot, DevHome | Новые пользователи получат мусорные приложения | 🔴 |
| 7.2 | **Удаление установленных AppX** | Удаляет пакеты из текущего профиля | Те же пакеты + `Get-AppxPackage -AllUsers \| Remove-AppxPackage` | Sysprep увидит пакеты у Admin, которых нет у Default User → crash | 🔴 |
| 7.3 | **Удаление Win32 bloatware** | Тихое удаление предустановленных Win32-программ через реестр Uninstall | OEM-утилиты, trial-версии, рекламное ПО | Занимают место, замедляют старт, могут конфликтовать | 🟡 |
| 7.4 | **Блокировка восстановления bloatware** | Запрет на повторную установку удаленных пакетов через реестр политики | `HKLM\SOFTWARE\Policies\Microsoft\Windows\CloudContent` → `DisableWindowsConsumerFeatures=1` | Windows может переустановить пакеты после первого подключения к интернету | 🔴 |
