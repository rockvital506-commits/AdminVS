### 📋 План создания саммари (Prompt-Ready Context)

Чтобы любая LLM (включая меня в новом чате) мгновенно восстановила весь контекст без потери инженерных нюансов, саммари должно быть структурировано по принципу **First Principles** (от железа к софту, с обоснованием "почему").

**Структура саммари:**
1. **Профиль и цели:** Кто мы, что строим, ограничения (бюджет, железо станций).
2. **Аппаратный слой (Сущности А и Б):** Физика дисков, контроллеры, интерфейсы.
3. **Логический слой (Разметка и ФС):** Кластеры, выравнивание, политики кэша/индексации.
4. **Загрузчик (Ventoy 1.1.10):** Синтаксис JSON, критичные флаги, плагин vhdboot, различия конфигов.
5. **Инженерные выводы и ловушки:** Ключевые "нельзя" и "почему так" (TRIM, сжатие, RAM-кэш).
6. **Словарь терминов и путей:** Быстрые ссылки на структуру папок.

```markdown
# ИНЖЕНЕРНЫЙ МЕТА-КОНТЕКСТ: VENTOY & WTG СБОРКА

## 1. ПРОФИЛЬ И ЦЕЛИ
- **Роль:** Начинающий системный инженер (ремонт/диагностика ПК).
- **Задача:** Двухдисковый комплекс реанимации (WTG + ISO-склад).
- **Ограничения:** Бюджет $0 (OpenSource/Free), целевые станции 2015+ года (Legacy/UEFI).
- **Хост:** Win11, Vivobook, WSL2, Docker.

## 2. АППАРАТНЫЙ УРОВЕНЬ (ФИЗИКА)
### Сущность А: Nexdrive P60 (470GB)
- **Тип:** Внешний NVMe-SSD. Мост: ASM2364/RTL9210 (UASP, аппаратный TRIM).
- **Интерфейс:** USB 3.2 Gen 2x2 (20 Гбит/с).
- **Назначение:** Windows To Go (VHDX), тяжелые образы, быстрый рандом 4K.

### Сущность Б: SD400 Pendrive (470GB)
- **Тип:** USB-Flash SSD (одночиповый SM3282). Без TRIM через USB, троттлинг при нагреве.
- **Интерфейс:** USB 3.2 Gen 1 (5 Гбит/с).
- **Назначение:** Склад ISO/WinPE/Linux, бэкапы Hasleo.

## 3. ЛОГИЧЕСКАЯ РАЗМЕТКА И ФС (ПРАВИЛО 2MB ALIGN)
*Выравнивание для всех разделов в DiskGenius: 4096 секторов (2MB).*

| Раздел | Сущность А (P60) | Сущность Б (SD400) | Обоснование |
|--------|------------------|--------------------|-------------|
| **1. VTOYEFI** | FAT32 (32MB) | FAT32 (32MB) | Штатный загрузчик Ventoy. |
| **2. Ventoy** | **NTFS, 64KB** | **exFAT, 512KB** | 64K NTFS = золотой стандарт для VHDX блоков. 512K exFAT = минимизация фрагментации ISO и износа flash. |
| **3. Tools** | **NTFS, 4KB** | **NTFS, 4KB** | Портативный софт. 4K кластер обязателен для работы NTFS-сжатия и корректной инициализации `.sys` драйверов. |

**Системные политики (Win11 Host):**
- **Индексация:** ❌ Отключена на ВСЕХ разделах обоих дисков (ускоряет Safe Remove, снижает износ).
- **Кэш записи:** P60 = `Оптимальная производительность` (требует Safe Remove). SD400 = `Быстрое удаление`.
- **TRIM:** Включен только для P60 (NTFS+UASP). На SD400 (exFAT) не работает.
- **Сжатие NTFS:** 
  - На разделах 2 (64K/512K) — технически невозможно/не поддерживается.
  - На разделе 3 (4K): На P60 — **выборочно** (только Logs/Config, ЗАПРЕЩЕНО для Drivers/Hardware_Mod). На SD400 — **отключено** (слабый контроллер, риск для .sys).

## 4. ЗАГРУЗЧИК: VENTOY 1.1.10
### Критичные архитектурные правила
1. **Синтаксис JSON:** `control` — это СТРОГО МАССИВ `[]` объектов `{"KEY": "VALUE"}`. Объект `{}` вызовет Syntax Error.
2. **Плагин VHDX:** `ventoy_vhdboot.img` **ОБЯЗАТЕЛЕН** для загрузки Windows из VHDX. Кладется в `[Раздел_Ventoy]\ventoy\ventoy_vhdboot.img`. Записи в JSON не требует.
3. **WIN_CACHE_DISABLE:** Флаг `1` отключает копирование образа в RAM на этапе GRUB2. WinPE/Linux грузят свои компоненты в RAM сами (через boot.sdi/initrd). Флаг **не ломает** WinPE/Linux, но критически ускоряет WTG и спасает от OOM.

### ventoy.json (Универсальный/Различия)
*Базовый набор флагов для обоих дисков:*
```json
{
  "control": [
    { "VTOY_WIN11_BYPASS_CHECK": "1" },
    { "VTOY_WIN11_BYPASS_NRO": "1" },
    { "VTOY_WIN_CACHE_DISABLE": "1" },
    { "VTOY_FILT_DOT_UNDERSCORE_FILE": "1" },
    { "VTOY_MAX_SEARCH_LEVEL": "max" },
    { "VTOY_MENU_TIMEOUT": "-1" },
    { "VTOY_DEFAULT_KBD_LAYOUT": "QWERTY_USA" },
    { "VTOY_SECONDARY_BOOT_MENU": "1" },
    { "VTOY_VHD_NO_WARNING": "1" }
  ]
}
```
**Различия в конфигах:**
- **P60:** Содержит секцию `"theme"` (GUI) и `"theme_legacy"` (GUI 1024x768). Цвет `#10a1d8`.
- **SD400:** Секция `"theme"` **УДАЛЕНА** (экономия места на 512K кластере, визуальное отличие). `"theme_legacy"` = `CLI` (гарантия работы на старом Legacy BIOS 2015+).

## 5. ИНЖЕНЕРНЫЕ ВЫВОДЫ И ЛОВУШКИ (FIRST PRINCIPLES)
- **Почему один JSON лучше двух?** Ventoy парсит JSON до инициализации FS. Флаги работают на уровне GRUB2. Единый файл упрощает синхронизацию FreeFileSync. (Но тема удалена на SD400 для визуального отличия в меню).
- **Почему нельзя форматировать Раздел 2 после установки Ventoy?** Ventoy пишет boot-код в PBR раздела 2. Форматирование затрет UUID и загрузчик. Правильный путь: Удалить раздел в DG → Создать заново с нужным кластером → Скопировать ventoy.json.
- **Почему RUSSIAN раскладка запрещена?** В среде GRUB2/BIOS корректно работает только `QWERTY_USA`. Русская вызовет `Invalid key`.
- **Драйверы:** `ventoy.json` НЕ инжектирует `.inf/.sys`. Драйверы для WinPE/WTG подгружаются через `Startnet.cmd`, `autounattend.xml` или вшиты в образ.
