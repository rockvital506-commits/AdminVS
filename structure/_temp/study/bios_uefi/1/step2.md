### 📦 Ядро: UEFI фазы (фокус DXE)
| Фаза | Назначение | Ключевые объекты | Роль в инициализации |
|------|------------|------------------|----------------------|
| **SEC** | Минимальный старт CPU | CAR (Cache-as-RAM), Security Core | Вектор сброса, проверка подписи FV, подготовка временной памяти |
| **PEI** | Ранняя инициализация чипсета | PPI (PEI-to-PEI Interface), FFS/FV parser, PEIMs | Инициализация RAM, PCIe Root Complex, базовая шина SMBus, поиск DXE IPL |
| **DXE** | **Драйверная среда** | **DXE Core, DXE Drivers, Protocols, Depex** | **Полная инициализация контроллеров/шин, публикация протоколов, генерация ACPI** |
| **BDS** | Выбор загрузчика | BootManager, NVRAM `BootOrder`, Device Paths | Сканирование ESP, запуск `bootmgfw.efi`/`GRUB`, передача управления TSL |
| **RT** | Runtime Services | `SetVariable`, `GetTime`, Reset | Фоновые вызовы ОС к прошивке после загрузки ядра |



[MAIN] 📖 Подробный разбор: UEFI фазы (фокус DXE)

### 🔹 Как работает инициализация до передачи управления OS
1. **Питание → SEC → PEI**: Железо "просыпается". RAM тестируется, PCIe Root Complex получает базовые регистры, память переключается в нормальный режим. Всё происходит в темноте (нет видео-вывода).
2. **Переключение в DXE**: PEI находит `DxeCore.efi` (DXE IPL), загружает в RAM, передает управление. С этого момента работает **планировщик**.
3. **DXE Core запускает цикл**:
   - Сканирует FV (Firmware Volume) на наличие `DXE Driver`.
   - Парсит `Depex` каждого драйвера.
   - Строит очередь загрузки: если `Protocol A` уже есть → драйвер выполняется. Если нет → ждет.
   - При выполнении драйвер инициализирует **железо** и публикует **протокол** (GUID + набор функций).
4. **Пример цепочки NVMe-загрузки**:
   `PciBusDxe` (enum PCIe) → `NvmeDxe` (инициализирует контроллер, маппинг BAR) → публикует `EFI_BLOCK_IO_PROTOCOL` → `FAT32Dxe` видит раздел → публикует `EFI_SIMPLE_FILE_SYSTEM` → `BootManagerDxe` (BDS) находит `\EFI\Microsoft\Boot\bootmgfw.efi` → передает управление.
5. **Генерация ACPI**: Перед выходом из DXE прошивка собирает данные о шинах, прерывиях, CPU topology, упаковывает в таблицы ACPI. Windows читает их при старте ядра, чтобы знать, где IRQ, DMA, BAR.
6. **BDS → TSL → OS**: UEFI больше не управляет железом напрямую. Она отдает ОС `Boot Services` таблицу. После вызова `ExitBootServices()` UEFI переходит в режим RT (только время, переменные, сброс).

### 🔹 Почему протоколы и Depex критичны для диагностики
- **Протокол** = интерфейс. Если `EFI_USB_IO_PROTOCOL` не опубликован → флешка не видна. Причина: драйвер `UsbBusDxe` не загрузился из-за конфликта ресурсов или битого BAR.
- **Depex** = порядок. Если драйвер `A` требует `B`, а `B` требует `A` → deadlock → POST зависает на `DXE` этапе (часто сопровождается кодом ошибок `0x0E`, `0x0F` или кодом вендора `99`).
- **Барьер PEI/DXE**: Всё до DXE — низкоуровневое, асинхронное, без стандартных API. Всё после DXE — стандартизировано. Поэтому "завис на логотипе ASUS/Dell" почти всегда = DXE или BDS.

[IF SOFT] 🎓 Ментор: пояснения для beginner
- `Аналогия`: Представь UEFI как аэропорт. 
  - PEI = открытие ВПП и запуск РЛС (базовая инфраструктура).
  - DXE = диспетчерская. Самолеты (драйверы) не взлетают, пока не получат слот (протокол). Depex = правила очередности. Без диспетчера — пробка.
  - BDS = выход на посадку. Выбирает, куда лететь (Windows/Linux).
- `Ловушка`: Не путай `PPI` (PEI) и `Protocol` (DXE). PPI — временный контракт на ранней фазе, Protocol — стабильный API, доступный до `ExitBootServices()`.
- `Инструмент для изучения`: `UEFITool` → открой `.cap`/`.rom` → `DXE` раздел → посмотри `Depex` секции. Пойми, почему `NvmeDxe` грузится после `PciBusDxe` (зависит от `EFI_PCI_IO_PROTOCOL_GUID`).
- `Масштабирование`: После освоения схемы перейди к `edk2` (сборка простого DXE-драйвера, `HelloWorld.efi`) и `Chipsec` (`chipsec_main -m common.bios_smi`). Это даст понимание, как протоколы вызываются на практике.

[RECOMMEND]
1. Нарисуй схему: `SEC → PEI → DXE(Core/Depex/Protocols) → BDS → TSL` и подпиши под каждой фазой, какие шины/контроллеры активируются.
2. Используй `UEFITool` на прошивке своего Vivobook (извлеки `.bin` через RWEverything/BIOS backup) → найди `DxeCore.efi` и 2-3 драйвера с Depex → проследи зависимости.

[ANTICIPATE]
- "Как узнать, на какой фазе зависает ноутбук?" → Включи `Post Code` в UEFI Setup (или слушать спикер/смотреть LED-коды). Коды `0x00-0x3F` = PEI, `0x40-0x7F` = DXE, `0x80+` = BDS/TSL.
- "Можно ли отключить Depex проверку?" → Нет, это жестко вшито в DXE Core. Можно только патчить прошивку (риск брика) или обходить через `CSM` (но Win11 не загрузится).

[MAIN] 🖼️ Схема инициализации UEFI (SEC → TSL)

```text
+-----------------------------------------------------------------------------------------------------------------------+
|                                         START OF BOOT (Power Good)                                                    |
+------+---------+--------------------------+-----------------------------------+---------------------------------------+
|  SEC |   PEI   |           DXE            |               BDS                 |                 TSL                   |
+------+---------+--------------------------+-----------------------------------+---------------------------------------+
| CPU  |  RAM    | PCI/PCIe Enumeration     | Boot Policy Execution             | Handover to OS Loader                 |
| Reset| Init    | (BAR allocation)         | (Read NVRAM BootOrder)            |                                       |
| CAR  | (SPD)   |                          |                                   |                                       |
|      |         | USB (XHCI) Init          | Console Init (GOP/TextOut)        | ExitBootServices()                    |
| FV   | Chipset | (SuperSpeed/SSIC)        |                                   |                                       |
| Parse| Init    |                          | Password/Setup UI                 | UEFI Runtime Mode                     |
| (FV) | (PCH)   | Storage (NVMe/SATA) Init |                                   | (Vars, Time, Reset only)              |
|      |         | (BlockIO/DiskIo Protocols| Device Path Resolution            |                                       |
| Sec  | SPI Flash| & FS Protocols)          |                                   | ACPI Tables Passed to OS              |
| Core | Access  |                          |                                   |                                       |
|      |         | ACPI Table Generation    | Legacy/CSM Option ROM Execution   | OS Kernel Starts                      |
|      |         | (MADT/FACP)              | (If Enabled)                      |                                       |
|      |         |                          |                                   |                                       |
+------+---------+--------------------------+-----------------------------------+---------------------------------------+
  ⬇        ⬇                 ⬇                          ⬇                                 ⬇
  CPU    RAM/SPI            DISK/USB                   BOOT MENU                        WINDOWS
 Only   Detected            Visible                    Appears                          Kernel
```

**📝 Пояснения по фазам:**
*   **SEC/PEI:** «Темная зона». Нет видео. Работает только спикер (бипы) или POST-карта. Инициализируется **только** то, что нужно для запуска DXE Core (RAM, SPI, базовый чипсет).
*   **DXE:** «Зона драйверов». Включается всё остальное: USB, NVMe, GPU (GOP), сеть. Собираются таблицы ACPI.
*   **BDS:** «Зона выбора». Появляется картинка (GOP), работает клавиатура, показывается меню.
*   **TSL:** «Передача». UEFI отдает управление ядру, сама сворачивает драйверы устройств, оставляя только Runtime Services.

[MAIN] 📋 Шпаргалка: Ситуации и Диагностика UEFI Фаз

*Фокус: Быстрая локализация проблемы по симптомам.*

### 🔹 Ситуация 1: «Зависание на логотипе вендора (бесконечный спиннер)»
*   **Фаза:** `DXE → BDS` (переход).
*   **Вероятная причина:** Конфликт драйвера периферии (USB-устройство), зависание `Depex` (циклическая зависимость), сбой инициализации NVMe.
*   **Алгоритм действий:**
    1.  **Изоляция:** Отключи все USB-устройства (кроме клавы), вынь SD-карты.
    2.  **Сброс:** `Hard Reset` (удерживать Power 15 сек).
    3.  **Инструмент:** Если есть доступ к UEFI Setup → `Load Defaults`.
    4.  **Цель:** Войти в Setup или увидеть сообщение об ошибке.
*   **Результат:**
    *   ✅ **Ожидаемый:** Загрузка в Setup/OS. → *Вывод:* Проблема в периферии или кэше настроек.
    *   ❌ **Неожиданный:** Зависание сохраняется без USB. → *Вывод:* Проблема внутри (NVMe/RAM). Включи `POST Code` в Setup (если доступно) или слушай спикер. Коды `0x5x-0x7x` = DXE (драйверы).

### 🔹 Ситуация 2: «Системный динамик издает длинные/короткие сигналы, экран черный»
*   **Фаза:** `PEI` (до инициализации видео).
*   **Вероятная причина:** Ошибка тренировки памяти (RAM Training), сбой SPD, критическая ошибка процессора.
*   **Алгоритм действий:**
    1.  **Диагностика:** Считай бипы (мануал к Vivobook/ASUS). 3 длинных = RAM error (часто).
    2.  **Действие:** Переподключи модули RAM. Очисти контакты.
    3.  **Инструмент:** Визуальный осмотр слотов.
    4.  **Цель:** Прекращение сигналов, появление изображения.
*   **Результат:**
    *   ✅ **Ожидаемый:** Один короткий бип, картинка. → *Вывод:* Плохой контакт или сбойный модуль RAM.
    *   ❌ **Неожиданный:** Бипы продолжаются с одним модулем. → *Вывод:* Слот или контроллер памяти в CPU. Требуется сервис.

### 🔹 Ситуация 3: «В BIOS/UEFI не видно NVMe SSD»
*   **Фаза:** `DXE` (PCIe Enumeration → Storage Init).
*   **Вероятная причина:** Диск не отвечает на PCI Enum, сбой питания (PMIC), режим контроллера (RAID/VMD vs AHCI).
*   **Алгоритм действий:**
    1.  **Проверка:** Зайди в Setup → Advanced → NVMe/SATA Config.
    2.  **Настройка:** Если есть `VMD Controller` (Intel Volume Management) → попробуй переключить `Disabled` (предупреждение: может потребовать reinstall Win).
    3.  **Инструмент:** `UEFI Shell` (если доступна) → `map -r`. Команда принудительно пересканирует шины.
    4.  **Цель:** Увидеть диск в списке `blk0`, `fs0` или в меню Setup.
*   **Результат:**
    *   ✅ **Ожидаемый:** Диск появился в `map`. → *Вывод:* Проблема была в драйвере VMD или инициализации.
    *   ❌ **Неожиданный:** Диска нет ни в Setup, ни в Shell. → *Вывод:* Аппаратный сбой диска или слота M.2.

### 🔹 Ситуация 4: «USB-клавиатура не работает в BIOS, но работает в Windows»
*   **Фаза:** `DXE` (USB Init) → `BDS` (Legacy Support).
*   **Вероятная причина:** `XHCI Hand-off` выключен, `Legacy USB Support` выключен. Windows использует свой драйвер, BIOS — встроенный.
*   **Алгоритм действий:**
    1.  **Поиск:** Зайди в BIOS (если возможно мышкой или другой клавиатурой).
    2.  **Настройка:** Advanced → USB Config.
    3.  **Действие:** Включи `Legacy USB Support` = `Enabled`, `XHCI Hand-off` = `Enabled`.
    4.  **Цель:** Клавиатура мигает (NumLock) сразу при включении.
*   **Результат:**
    *   ✅ **Ожидаемый:** Клавиатура работает в Setup. → *Вывод:* Настройки BIOS.
    *   ❌ **Неожиданный:** Не работает даже в другом порту. → *Вывод:* Сбой контроллера XHCI на уровне железа или прошивки.

### 🔹 Ситуация 5: «Boot Loop (перезагрузка на логотипе Windows)»
*   **Фаза:** `TSL` (Handover failure) или `BDS` (Boot Policy).
*   **Вероятная причина:** `ExitBootServices` завершается с ошибкой (конфликт GOP драйвера и ядра), битый `bootmgfw.efi`.
*   **Алгоритм действий:**
    1.  **Изоляция:** Отключи `Fast Boot` в BIOS.
    2.  **Безопасный режим:** Прерви загрузку 3 раза (кнопкой питания) → вызов `Automatic Repair`.
    3.  **Инструмент:** `bcdboot` через WinPE (если не грузится).
    4.  **Цель:** Вход в среду восстановления.
*   **Результат:**
    *   ✅ **Ожидаемый:** Попадает в Recovery. → *Вывод:* Проблема в драйвере Windows или BCD.
    *   ❌ **Неожиданный:** Цикл продолжается даже при попытке входа в Recovery. → *Вывод:* Критическая ошибка ACPI или ядра. Попробуй отключить `Secure Boot`.

### 🔹 Ситуация 6: «Secure Boot Violation / Image failed verification»
*   **Фаза:** `BDS` (Security Check).
*   **Вероятная причина:** Загрузчик (Linux, Ventoy, старый WinPE) не подписан ключом Microsoft.
*   **Алгоритм действий:**
    1.  **Действие:** Setup → Security → `Secure Boot` = `Disabled` (для теста).
    2.  **Альтернатива:** Если нужно включить: `Key Management` → `Restore Factory Keys`.
    3.  **Инструмент:** `mokutil` (в Linux) или `sbkeysync` (в Win).
    4.  **Цель:** Успешная загрузка образа.
*   **Результат:**
    *   ✅ **Ожидаемый:** Загрузка прошла. → *Вывод:* Проблема подписи.
    *   ❌ **Неожиданный:** Ошибка сохраняется при `Disabled`. → *Вывод:* Глюк NVRAM. Сделай `Clear Secure Boot Keys` → `Reset`.

### 🔹 Ситуация 7: «Сброс времени и настроек BIOS при каждом выключении»
*   **Фаза:** `DXE` (NVRAM Variable Service) → `RT` (RTC).
*   **Вероятная причина:** Села батарейка CMOS, corrupted region NVRAM в SPI Flash.
*   **Алгоритм действий:**
    1.  **Проверка:** Мультиметр батарейки CR2032 (должно быть >2.5V).
    2.  **Действие:** Замена батарейки.
    3.  **Инструмент:** `RWEverything` → чтение `NVRAM` региона (только чтение!).
    4.  **Цель:** Сохранение настроек после перезагрузки.
*   **Результат:**
    *   ✅ **Ожидаемый:** Настройки сохраняются. → *Вывод:* Батарейка.
    *   ❌ **Неожиданный:** Батарейка новая, но сброс идет. → *Вывод:* Коррупция SPI-флеша (Region NVRAM). Требуется перепрошивка BIOS программатором или через Vendor Recovery.

[IF SOFT] 🎓 Ментор: Как пользоваться шпаргалкой
1.  **Правило «Света»:** Если нет изображения — это `PEI`. Если есть логотип — это `DXE/BDS`. Если есть кружок Windows — это `TSL`. Это сокращает поиск на 80%.
2.  **Не паникуй при `Secure Boot`:** Это самая частая "ошибка" у новичков при загрузке флешек. Отключение — штатная процедура для диагностики, не бойся (включишь потом).
3.  **Depex и зависания:** Если ноутбук виснет на 90% прогресса (если он есть) или на логотипе с точками — это почти всегда драйвер устройства. Отключай периферию по одной.
4.  **Безопасность:** Никогда не прошивай BIOS (`DXE` recovery) от другой модели, даже если "разъем подходит". Это кирпич. Используй только официальные `.cap`/`.rom` с сайта производителя.

[RECOMMEND]
1.  Распечатай схему фаз и повесь рядом с рабочим местом. При диагностике пальцем указывай, где, по твоему мнению, застрял процесс.
2.  Скачай `UEFITool` и открой файл BIOS своего ноутбука. Найди раздел `DXE` — посмотри, сколько там драйверов. Это даст понимание масштаба "черного ящика".

[ANTICIPATE]
