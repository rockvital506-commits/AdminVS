
### Исследование: уровни абстракции данных как основа выбора утилиты

Ключевой вывод: оптимальная утилита выбирается не по бренду, а по самому низкому уровню абстракции, на котором ещё можно решить задачу без лишних преобразований. Чем ниже уровень — тем выше полнота и шанс восстановления, но тем выше риск, объём данных и требования к аккуратности. Чем выше уровень — тем безопаснее и быстрее, но часть структуры уже потеряна.

### 1. Базовое исследование: уровни абстракции данных

Наблюдение

Все перечисленные утилиты работают с одним из пяти уровней данных:

L0 — Сектора / устройство

сырые блоки, GPT/MBR, boot sectors, служебные области

максимальная полнота

L1 — Разметка / разделы

GPT/MBR, EFI, MSR, NTFS/exFAT/FAT32, размеры и флаги

структура диска

L2 — Файловая система

MFT, каталоги, ACL, альтернативные потоки, метаданные

точное восстановление

L3 — Образы и контейнеры

ADI, VHDX, WIM, ISO, IMG как переносимые артефакты

упаковка и перенос

L4 — ОС и конфигурация

BCD, драйверы, службы, автозапуск, офлайн-реестр, компоненты Windows

ремонт без копирования

Главный принцип выбора

1. Сначала решаем задачу на самом высоком безопасном уровне.

2. Если информации недостаточно или структура повреждена — опускаемся на уровень ниже.

3. При риске деградации накопителя первым действием становится фиксирующее чтение L0 → файл IMG/VHDX.

### 2. Дополнительное исследование A: «Сначала контейнер или сначала ремонт?»

Гипотеза

Для обратимых работ выгоднее сначала создать контейнер, а уже потом редактировать.

Проверка на типовых сценариях

| Сценарий                                   | Оптимальный первый шаг                            |
| ------------------------------------------ | ------------------------------------------------- |
| Подозрение на деградацию SSD/HDD           | L0 → IMG (DMDE / ddrescue-подход)                 |
| Нужно откатить Windows после экспериментов | L3 → System Backup / VHDX (Hasleo)                |
| Нужно починить BCD или драйвер офлайн      | L4 напрямую (Bootice / DISM++)                    |
| Нужно извлечь удалённые файлы              | L2, без записи на исходный диск (R-Studio / DMDE) |

Вывод A

правило 1

Если предстоит много правок, сначала делаем контейнер/образ (L3). Если предстоит спасение умирающего носителя, сначала делаем сырое чтение (L0). Ремонт до фиксации данных повышает риск потери состояния.

### 3. Дополнительное исследование B: «Что теряется при переходе между уровнями?»

| Переход        | Что обычно теряется                                                                          |
| -------------- | -------------------------------------------------------------------------------------------- |
| L0 → L1        | Свободные сектора, удалённые хвосты файлов, часть forensic-данных.                           |
| L1 → L2        | Информация о соседних разделах и общей геометрии диска.                                      |
| L2 → L3 (WIM)  | Точная структура тома, некоторые FS-метаданные, boot-контекст.                               |
| L2 → L3 (VHDX) | Почти ничего, если копируется целый раздел/диск; теряется привязка к физическому устройству. |
| L3 → L4        | Ничего не теряется, но меняется только конфигурация ОС, а не содержимое носителя целиком.    |

Вывод B

правило 2

WIM ≠ полный снимок системы.

WIM хорош для развёртывания Windows, но не заменяет полный backup/clone/VHDX/IMG, когда важны EFI, GPT, BCD, Recovery и состояние разделов.

### Итоговый алгоритм выбора (сжатая памятка)

4 шага

1. Носитель нестабилен?

   → L0 → DMDE (read-only image).

2. Нужно быстро вернуть Windows?

   → L3 → Hasleo Backup / VHDX.

3. Не грузится, драйверы/BCD/службы?

   → L4 → DISM++ / Bootice / FRST.

4. Нужны удалённые файлы?

   → L2 → R-Studio или DMDE, а если структура уничтожена — PhotoRec.

Суть универсальности

Наибольшую универсальность в твоём наборе дают DMDE + Hasleo Backup + DISM++: они покрывают фиксацию состояния (L0), перенос/откат (L3) и ремонт конфигурации (L4). Остальные утилиты становятся специализированными усилителями: TestDisk — структура разделов, R-Studio — глубокий FS recovery, PhotoRec — RAW carving, Bootice — загрузка, WinNTSetup — развёртывание, Rufus — носители.
