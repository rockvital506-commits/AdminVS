
[MAIN] 🔧 **flashrom** — утилита для работы с флеш-памятью (SPI/EEPROM)

### 📦 Короткое определение
**flashrom** — это кроссплатформенная утилита с открытым исходным кодом для **обнаружения, чтения, записи, проверки и стирания** флеш-чипов [[3]]. Она часто используется для прошивки BIOS/UEFI/coreboot/firmware как **в системе** (через `internal` программатор), так и **внешне** (через аппаратные программаторы типа `CH341A`, `Bus Pirate`, `Dediprog`) [[2]][[11]].

---

### 🎯 Для чего нужен в диагностике/ремонте
| Задача | Как помогает flashrom |
|--------|----------------------|
| **Бэкап прошивки перед ремонтом** | `flashrom -p ch341a_spi -r backup.bin` — полное чтение чипа для восстановления [[23]] |
| **Восстановление "кирпича"** | Запись валидного образа после аппаратного сбоя: `flashrom -p ch341a_spi -w good.bin` [[21]] |
| **Проверка целостности** | `--verify` сравнивает записанный образ с исходным, ловит ошибки записи [[2]] |
| **Работа с регионами (IFD/FMAP)** | `-i bios -w bios.bin` — обновить только BIOS-регион, не трогая ME/GBE [[2]] |
| **Управление write-protect** | `--wp-status`, `--wp-disable` — проверка/снятие защиты от записи [[30]][[36]] |
| **Скриптинг массовых операций** | `-j report.json`, `/Command=` — автоматизация приёмки техники |

### ⚙️ Базовый синтаксис и флаги
```bash
# ОБЯЗАТЕЛЬНО: указать программатор (-p) для любой операции с чипом
flashrom -p <programmer> [операция] [доп.флаги]

# 🔹 Основные операции:
# Чтение (бэкап)
flashrom -p ch341a_spi -r backup.bin

# Запись (с авто-стиранием + верификацией)
flashrom -p ch341a_spi -w new_image.bin

# Проверка (без записи)
flashrom -p ch341a_spi -v reference.bin

# Только определение чипа (безопасный тест)
flashrom -p ch341a_spi

# 🔹 Важные флаги:
# -c <chip>     → принудительный выбор чипа (если авто-детект не сработал)
# -i <region>   → работа только с регионом (bios/me/gbe при использовании --ifd)
# --ifd         → использовать Intel Firmware Descriptor для разбивки на регионы
# --fmap        → использовать coreboot FMAP для разбивки
# --wp-status   → показать статус write-protect
# -n            → пропустить верификацию (не рекомендуется!)
# -V            → подробный вывод (можно -VV, -VVV для отладки)
# -o <logfile>  → сохранить полный лог (лучше, чем перенаправление вывода)
```

### 🛠️ Практический пример: бэкап/восстановление на твоем стеке
```bash
# 1. Подготовка (Linux/WSL2)
sudo apt install flashrom libftdi1 libusb-1.0-0

# 2. Подключи CH341A к SPI-чипу (соблюдая Pin 1, напряжение 3.3В) [[11]]

# 3. Определи чип (безопасно, только чтение)
flashrom -p ch341a_spi
# Ожидай: "Found Winbond flash chip "W25Q128" (16384 kB, SPI)"

# 4. Сделай бэкап + лог + верификацию
flashrom -p ch341a_spi -r backup_$(date +%Y%m%d).bin -o backup.log -V

# 5. (Опционально) Проверь целостность бэкапа
sha256sum backup_*.bin > backup.sha256

# 6. Если нужно восстановить:
flashrom -p ch341a_spi -w backup_20260510.bin --verify -o restore.log
```

⚠️ **Критичные предупреждения**:
- **Не используй `internal` программатор на ноутбуках** — встроенный EC может конфликтовать и "окирпичить" устройство [[3]].
- **Всегда делай бэкап перед записью** — это твой единственный путь к откату [[23]].
- **Проверяй напряжение**: 3.3В для большинства современных чипов, 5В — только для старых (см. даташит) [[11]].
- **Не записывай регионы `ME`/`GBE` без понимания** — это может нарушить работу платформы [[2]].

### 🔗 Как flashrom вписывается в твой инструментарий
```
[Диагностика]          [Анализ]              [Восстановление]
     ↓                       ↓                       ↓
chipsec (аудит) → UEFITool (структура) → flashrom (чтение/запись)
     ↓                       ↓                       ↓
Найти проблему    →   Понять, что менять   →   Безопасно записать
```

| Инструмент | Роль | Когда использовать |
|------------|------|-------------------|
| **chipsec** | Аудит безопасности | Проверка Secure Boot, TPM, SPI locks *в работающей системе* |
| **UEFITool** | Анализ структуры | Разбор `.bin`-образа, поиск драйверов, модификация *файла* |
| **RWEverything** | Низкоуровневый доступ | Чтение регистров *в реальном времени* (EC, SMBus, PCI) |
| **flashrom** | Работа с чипом | **Физическое** чтение/запись прошивки в чип (аппаратный уровень) |

### 📋 Чек-лист безопасности перед использованием
1. [ ] Есть **валидный бэкап** оригинального чипа? (`-r` + `--verify`)
2. [ ] Образ для записи **проверен** (хеш, структура в UEFITool)?
3. [ ] Напряжение программатора **соответствует** чипу (3.3В/5В)?
4. [ ] Подключение **правильное** (Pin 1, CS/MOSI/MISO/SCK/GND)?
5. [ ] Понимаю, **какие регионы** записываю (только `bios`, не `ME`)?
6. [ ] Есть **план отката** (бэкап + способ записать его обратно)?

[IF SOFT] 🎓 Ментор: пояснения для beginner
- `internal` vs `ch341a_spi`: `internal` = прошивка из-под ОС (рискованно на ноутбуках), `ch341a_spi` = внешний программатор (безопаснее, требует физического доступа) [[3]][[11]].
- **Почему `-p` обязателен**: flashrom поддерживает 40+ типов программаторов. Без `-p` он не знает, как общаться с железом.
- **`--verify` — не опция, а необходимость**: запись без проверки = "надеюсь, что записалось". С верификацией = "знаю, что записалось".
- **Если чип не определяется**: попробуй `-c "W25Q128"` (имя из вывода `flashrom -L`), проверь подключение, напряжение, драйверы (`lsusb` для CH341A).
- **Масштабирование**: После освоения базовых команд переходи к `--ifd` (работа с регионами) и `--wp-*` (управление защитой) — это даст профессиональный уровень контроля.

[RECOMMEND]
1. Создай шаблон-скрипт `fw_backup.sh`:
   ```bash
   #!/bin/bash
   DATE=$(date +%Y%m%d_%H%M)
   flashrom -p ch341a_spi -r backup_${DATE}.bin -o log_${DATE}.txt -V
   sha256sum backup_${DATE}.bin > backup_${DATE}.sha256
   echo "✅ Бэкап завершён: backup_${DATE}.bin"
   ```
2. Потренируй чтение/верификацию на **нерабочей плате** перед работой с клиентским устройством.

[ANTICIPATE]
- "Как узнать, какой у меня чип, без даташита?" → `flashrom -p ch341a_spi` покажет детектированное имя. Если "unknown" — попробуй `-c "SFDP-capable"` для авто-определения по SFDP-таблице [[9]].
- "Можно ли использовать flashrom из Windows?" → Частично: внешние программаторы (`ch341a_spi`, `dediprog`) работают, но `internal` — нет [[3]]. Проще: использовать WSL2 или загрузиться с Linux LiveUSB.
